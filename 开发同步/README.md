# 多窗口开发同步

这个目录用于协调共享同一工作区的多个 Codex 开发任务，避免不同窗口同时改动同一功能或文件。

## 工作方式

- 永久规则保存在项目根目录 `AGENTS.md` 和本文件中。
- 每个会修改仓库的任务，在 `进行中/` 内建立一份只属于自己的临时登记文件。
- 开发前读取全部进行中登记，先判断功能和文件是否冲突，再开始修改。
- 开发期间及时更新自己的范围、文件和进展。
- 开发完成并验证后，只删除自己的临时登记文件。

不要把所有任务写入同一个共享文件。独立登记可以避免两个窗口互相覆盖内容，也可以防止一个任务完成时误删其他任务的状态。

## 文件命名

`YYYYMMDD-HHmm-任务简称-任务ID后8位.md`

示例：`20260901-1430-关卡编辑器-aaf564e3.md`

时间统一使用 Asia/Shanghai（UTC+8）。任务 ID 可从当前 Codex 任务信息获得；无法取得完整 ID 时，使用能区分当前窗口的稳定短标识。

## 登记模板

```md
# 任务名称

- 任务 ID：
- 状态：开发中
- 开始时间：YYYY-MM-DD HH:mm（Asia/Shanghai）
- 最后更新：YYYY-MM-DD HH:mm（Asia/Shanghai）

## 工作范围

- 

## 计划修改文件

- `待确认`

## 当前进展

- 已完成：
- 正在处理：
- 尚未处理：

## 冲突提醒

- 无；如发现重叠，在这里写明涉及的任务和文件。
```

## 状态约定

- `开发中`：正在修改或验证。
- `等待用户`：任务尚未完成，正在等待用户选择、授权或素材。
- `受阻`：因其他进行中任务的重叠或外部条件暂时不能继续。

已完成的任务不保留登记文件。历史结果由代码、正式设计文档和版本记录承载；这个目录只表示“现在谁正在做什么”。

## 冲突处理

1. 文件不同且功能不同：可以并行开发。
2. 文件相同但修改区域明确独立：先向用户说明，再谨慎并行；每个任务仍只维护自己的登记。
3. 功能或修改区域重叠：后开始的任务暂停重叠工作，不能覆盖先开始任务的未完成改动。
4. 检查失败来自另一任务正在施工的范围：记录并告知用户，不擅自修复或回滚。
5. 无法确认登记是否失效：保留登记并向用户确认，禁止自动清理。
