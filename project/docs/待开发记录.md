## 1. 护盾视觉参数调优（后期）
- **状态说明**：贴合载具底盘体系 Alpha 轮廓的薄层护盾、常态内部场、边缘能量流、单次受击六边形扩散、开展和破盾碎片均已实现；本项只记录后续视觉调参，不代表护盾功能尚未完成。
- **贴身护盾范围（已实现）**：轮廓由主体、底盘、履带或轮胎组成，炮塔和炮管不参与轮廓提取。炮塔绘制在护盾视觉层下方，因此位于车体范围内的部分仍会呈现被护盾覆盖的观感；炮塔或炮管伸出护盾轮廓不需要补齐护盾，也不触发动态轮廓重算。护盾描边、沿边能量流、受击波纹和破盾碎片均使用同一底盘体系轮廓。
- **形状与铺设（当前基准）**：底盘体系贴图按 `BASE_CELL=32px` 的原生比例合成 Alpha 遮罩并缓存，轮廓向外扩张 `3px`；转向轮采用 `-30° / 0° / +30°` 固定包络，避免每帧重建轮廓；贴图未就绪时回退载具占格形状。受击六边形尺寸为 `max(13px, 单格尺寸×0.72)`。
- **内部场体（当前基准）**：底色 `rgb(76,190,207)`，基础透明度随剩余护盾由 `2.2%` 增至 `3.8%`；场体素材双层反向漂移，第一层透明度系数约 `0.62~0.90`，第二层约 `0.46~0.70`，并带小幅位移和旋转。
- **常态边缘（当前基准）**：边缘主线 `rgb(225,255,255)`，基础透明度随剩余护盾为 `34%~46%`；亮度采用双频呼吸，约在基准值的 `±15.5%` 内变化，线宽约 `±6.5%` 变化；柔光色为 `#B7F4F7`。
- **沿边能量波峰（当前基准，已回到初版）**：每圈约 `6.67 秒`，波头宽度参数 `0.055`、拖尾宽度 `0.11`、拖尾间距 `0.13 圈`；波峰只调制原有边缘柔光采样点的亮度（增益基线 `0.82`、波头最高增加 `0.72`、拖尾最高增加 `0.16`），不再叠加独立高亮光带或亮色描线。
- **单次受击（当前基准）**：六边形按“命中格 → 紧邻一圈 → 外围第二圈”播放一次扩散；三层峰值亮度系数依次为 `1.00 / 0.62 / 0.34`。正常状态每圈延迟为受击事件进度的 `0.14`、单圈脉冲持续 `0.26`；破盾状态对应为 `0.12 / 0.34`，播放结束后全部隐藏。
- **护盾开展（当前基准）**：总时长 `0.82 秒`；从 `50%` 尺寸、`6%` 透明度开始平滑开展；末段轻微回弹，最大额外缩放约 `1.8%`；开展期间边缘亮度最高额外增强 `70%`。
- **破盾（当前基准，整体柔性崩解版）**：命中位置只负责最初的亮核、电弧和六边形波纹，护盾本体不从命中点向外传播破碎。内部场体在 `0.26 秒` 内整体淡出并最多收束约 `8%`；完整外缘共同失稳，各段只在 `0.08 秒` 内做随机错峰并各自淡出约 `0.16 秒`。碎片发射点以约 `0.72` 世界单位间距的交错网格**平均覆盖整个贴身护盾 Alpha 轮廓范围**，并确定性剔除 `60%` 采样点，使主碎片总量约为完整采样方案的 `2/5`；所有区域在 `0.12 秒` 内随机错峰释放，每点 `2~3` 片。主碎片为**无描边的不规则三角形、四边形、狭长条和锐角半透明能量薄片，不使用六边形造型**，分为 `30%` 大型缓慢、`50%` 标准、`20%` 狭长高速三类，并带淡青/近白青/深青色差和少量初生亮度增强；基础尺寸为护盾短边的 `7%`（限制 `0.20~0.60` 世界单位），保留 `±42%` 单片随机差异，基准速度 `3.5`、寿命 `1.05 秒`，飞散期间每秒缩小约 `8%`。独立冰晶层按每片主碎片 `45%` 的确定性概率生成，长期总量约为主碎片的 `45%`；尺寸为主碎片的 `24%`、初速 `5.4`、寿命约 `1 秒`（`±18%`），阻力 `6.5`，表现为高速起步后快速减速漂浮，采用近白青细长锐角造型和轻微闪烁。整体运动方向混合径向与较强切向分量，并穿插少量短命余辉粒子。
- **后续重点调整**：轮廓外扩距离与细碎轮廓平滑程度；内部场体的可见度与动态幅度；边缘呼吸幅度/频率；能量波峰的方向、速度、长度和对比度；受击扩散节奏；破盾闪光强度、碎片密度/尺寸/寿命。当前数值均为临时视觉基准，确定最终风格后再固化；若需要多种护盾外观，应将这些数值移入可配置的护盾视觉预设，而不是继续写死在渲染代码中。
- **后续工作量：小~中**（单纯调参为小；做成护盾视觉预设与编辑器参数为中）

## 2. 统一战斗 HUD 后续精修
- **基础版已实现**：战车状态区贴左上角显示结构/护盾叠加条、热量条、速度、资源和四向装甲摘要，任务目标位于其下；右下按当前炮塔显示独立自动开火按钮及各自弹药/能量竖条，旧全局弹药/能量 HUD 已删除。
- **顶部边界**：不再显示独立的任务进度窗和敌人数量窗，顶部右侧只保留任务、事件、性能监控缩放与 DEBUG 快捷入口；波次、阶段或任务时间若后续确有常驻需求，应并入现有低遮挡面板，不重新增加横向大窗。右上仍可保留小地图与关键战场提示位置。
- **信息层级**：常驻区域只显示战斗中必须快速读取的数值；详细炮塔、模块、装甲与状态说明交由战斗内弹窗展示。目标面板与详细状态允许收起，但任务失败预警、资源不足和关键交互提示不得被隐藏。
- **视觉原则**：沿用现有米黄色军事面板、粗黑描边、红/黄状态色和像素字体；减少装饰性边框、投影和占位，不在战场画面上常驻绘制装甲边框。
- **响应式布局（基础版已实现）**：桌面与普通横屏沿四角和底边排布；矮屏/窄屏可收起左侧战车状态与任务目标，炮塔按钮改为单行横向滚动；竖屏时信息退到顶部快捷栏下方，炮塔栏横贯底部可用宽度；战斗根视口已接入刘海屏与圆角安全区。
- **战斗整备 HUD（已实现）**：战斗内整备不再打开老版全屏整备页，改为战场下方的轻量浮动 HUD；普通模式显示装配分，堡垒防御显示资源消耗，固定火力单位只开放炮塔。矮屏横屏精简为“已装装备 + 可用装备”两栏，竖屏采用上下分区；任务介绍中的完整预设管理页保持不变。
- **联动**：现有四向装甲、护盾、炮塔独立弹药/能量、热量和资源状态。
- **剩余工作量：小**（手机实机手感调优，以及资源不足、任务失败预警等关键提示优先级）。

## 3. 战斗内弹窗（后期）
- **功能范围**：战斗中点击炮塔、模块或对应 HUD 按钮后，弹出当前装备、装甲和状态的详细信息；常驻 HUD 不承载这些低频详情。
- **显示原则**：弹窗保持低遮挡、可快速关闭，并沿用统一军事面板视觉；任务失败预警、资源不足和关键交互提示的显示优先级高于普通详情弹窗。
- **组件复用**：复用整备界面的炮塔、模块、装甲与参数展示组件，保持信息结构和操作反馈一致；战斗状态下允许执行的操作由战斗规则单独约束，不直接继承整备界面的编辑权限。
- **联动**：战斗 HUD 负责入口与摘要，弹窗负责详情和允许的即时操作；两者读取同一份实时战斗状态。
- **工作量：中**（弹窗入口、实时状态绑定、遮挡与层级处理、共用展示组件接入）。

## 4. 事件条件分支与条件等待（后期待评估）
- **当前决定**：仅记录方案，是否正式实现仍需结合后续剧情和任务制作复杂度再决定；现阶段不进入事件指令列表。
- **条件分支候选**：复用统一条件编辑器，提供“如果 / 否则”两条动作序列，减少为了简单分支而创建多个事件与中间变量的需求。
- **条件等待候选**：在固定秒数等待之外，可等待条件满足、单位抵达、指定单位死亡、敌群清空或当前任务阶段结束；需要同时设计超时、目标被移除和关卡结束时的退出规则。
- **暂缓原因**：两者都会引入嵌套动作、长时间挂起和存档恢复问题；先通过已实现的“调用事件”、变量和独立事件组合验证实际需求。
- **工作量：中**（动作协议、编辑器嵌套、运行时挂起恢复、循环保护与回归）。

## 7. 导出/导入优化（后期）
- **当前决定**：暂不开发，继续作为后期项目保留，不阻塞现阶段关卡、战斗、编辑器和音频表现开发。
- **单文件原则**：完整项目的导出结果只生成一个项目包文件；导入时也只需选择这一个文件，不再让配置、图片和音频分别导入或导出。
- **项目包内容**：在单一容器中统一保存项目清单与版本、关卡、单位、炮塔、弹丸、模块、声音预设、全部引用配置、上传图片，以及 IndexedDB 中的 BGM/SE 原始文件与素材元数据；玩家进度、装备解锁与勋章数据是否随包携带，实施前再确定为必选或可选项。
- **格式建议**：使用带独立扩展名的压缩容器，例如 `.dfproject`；内部以清单文件记录数据版本、资源路径、大小和校验信息，便于迁移与损坏检查。
- **导入安全**：导入时先完成格式、版本、引用和素材完整性校验，再原子化写入；任一步失败都不得覆盖当前项目，并需提供错误项目说明。
- **兼容边界**：普通轻量配置口令可继续保留，但不携带大型图片或音频正文；完整备份和跨设备迁移统一使用单文件项目包。
- **工作量：中~大**（单文件二进制打包、图片与音频资源收集、引用重写、版本迁移、原子导入、容量提示及跨设备回归）。

## 8. 新单位设计（后期待评估）
- **当前决定**：本项统一收纳尚未立项的新单位形态，不进入当前及近期开发排期；先使用现有单位类型验证玩法需求，再决定是否选取其中的方案正式开发。
- **铰接载具**：由双节或多节车体组成，通过铰接夹角转向；若恢复开发，需要处理多刚体碰撞、分段渲染、车体连接约束、炮位跟随和复杂地形通过性。
- **混合飞行器**：垂直起降和低速阶段按旋翼飞行器悬停，高速前飞时让旋翼或推力机构倾转，并切换为固定翼巡航规则；若恢复开发，需要处理悬停、过渡、巡航三态运动、切换速度与时长、AI 预判和倾转动画。
- **共用原则**：阵营、受击、武器、飞行高度、关卡实例与事件继续复用统一单位系统，只为确定采用的新形态增加必要的运动和渲染协议。
- **立项条件**：需要先明确该单位能够提供现有履带、轮式、气垫、步行机甲、旋翼和固定翼单位无法替代的玩法价值，再进入方案细化和工作量评估。

## 9. 战场视野后续扩展
- **当前基础**：当前只采用“队伍当前可见 / 视野外阴影”两层结构，不保存未探索状态。玩家主控、玩家阵营单位与友方单位共享视野；多人 PVP 时同阵营玩家沿用同一视野并集。
- **未探索层（暂缓）**：后续如需要三层战争迷雾，再增加“未探索全黑 / 已探索压暗记忆 / 当前可见”状态、探索位图和存档规则；现阶段不开发。
- **高度与物体遮挡（暂缓）**：后续评估利用现有高度等级计算视线遮挡，高物体或墙体阻断地面单位视线；同时明确飞行高度、观察者高度、目标高度及连续 Autotile 物体外轮廓对可见区域的影响。
- **性能边界**：遮挡方案应采用低频可见多边形更新、空间索引和遮挡缓存，不能对每个像素或每帧全部物体执行射线检测；手机端压力测试通过后再立项。
- **联机边界**：多人模式中共享视野必须由服务端按队伍裁定，视野外敌方动态数据不得只依靠客户端遮罩隐藏。
- **工作量：中~大**（未探索层为中；高度、连续物体遮挡及联机服务端裁定合并实施为大）。
