# 关卡编辑器设计

> 更新日期：2026-08-28  
> 文档性质：当前实现与已确认设计的统一基准，不保存版本流水账。  
> 负责范围：关卡库、场景分层、地形与物体、关卡单位实例、事件、任务阶段、任务简报、关卡进度及其编辑流程。  
> 相关文档：《单位编辑器设计》《堡垒编辑器设计》《炮塔编辑器设计》《待开发记录》。尚未开发的内容只在《待开发记录》中维护。

## 1. 设计目标与边界

关卡编辑器用于把素材库、地形/物体类型库、单位库和事件系统组合成可以直接运行的完整关卡。编辑器负责“实例如何出现在本关、何时行动、任务如何流转”，不重复定义单位或武器本身的数据。

- 单位的外观、属性、炮位、预装炮塔和组合式 AI 原型来自单位编辑器。
- 弹丸数值与表现来自统一弹丸库；玩家、友方、敌方和中立敌对单位共用同一战斗系统。
- 阵营、控制器、关卡内移动行为和实例事件只在关卡中设置。
- 地形和物体的可复用类型由地形/物体类型库维护，关卡保存放置后的实例。
- 任务阶段保持独立“任务”页，不并入事件页。事件可以监听阶段结果并执行动作，但不替代任务流程本身。
- 已删除初始炮塔、旧交互物面板、选择空对象、旧核心/固定建筑/独立墙体编辑入口。对应内容应分别使用单位、物体或图块表达。

## 2. 编辑器框架

关卡编辑器位于现有 DEBUG 框架内，保留 DEBUG 标题栏、导出/导入/重置/关闭按钮及各编辑器切页，不进入独立全屏页面。关卡编辑器内部没有“退出编辑”按钮。

工作区由四部分组成：

1. 顶部工具栏：固定显示全部工具，切换层级时位置不变；当前层不可用的工具保持原位并禁用。
2. 左侧面板：在“关卡列表”和“关卡信息”之间切换。
3. 中央场景：占据左右面板之间的全部剩余空间，用于绘制、选择、移动和预览。
4. 右侧面板：根据当前层级和对象层子页显示图块、地形、物体、单位、事件或任务内容。

左右面板贴近界面边缘，顶部与工具栏贴合；编辑器卡片不使用投影。场景区域自行裁切世界内容，并同时提供横向和纵向滚动位置反馈。

## 3. 关卡库与草稿生命周期

### 3.1 多关卡库

关卡库保存稳定的关卡 ID、名称、完整关卡配置、下一关引用、资源奖励、装备解锁奖励、任务简报和备选出战车辆。库最多包含 50 个关卡，并维护一个活动关卡 ID。

左侧关卡列表提供：

- 按名称搜索；
- 新建、复制、删除；
- 上移、下移调整顺序；
- 单击切换当前编辑关卡；
- 显示序号、名称、任务阶段数、地图尺寸和伏击数量；
- 不显示“试玩”标记，但当前选中关卡仍作为保存后的活动/试玩关卡。

至少保留一个关卡。复制基于当前未保存草稿，避免丢失刚完成的修改。

### 3.2 编辑状态

- 进入关卡编辑器时载入完整关卡库，并为当前关卡建立草稿。
- 编辑期间暂停实际战斗，中央画布显示草稿内容。
- “保存”把当前草稿同步进关卡库；选中关卡继续作为活动关卡。
- 切换其他 DEBUG 编辑器或关闭 DEBUG 时，未保存内容按现有草稿退出规则处理。
- 镜头、缩放、当前切页、选中对象和网格显隐属于界面状态，不写入关卡数据。

### 3.3 全局撤销与重做

撤销/重做覆盖整个关卡编辑器，包括：

- 关卡的新建、复制、删除、排序和重命名；
- 关卡信息、简报、目标规则、出战车辆、关卡链和奖励；
- 地图尺寸、四层场景内容、单位、事件和任务阶段；
- 关卡变量、全局变量；
- 地形/物体类型库的编辑。

撤销跨关卡修改时自动回到发生变化的关卡。纯界面状态不产生历史记录。

## 4. 坐标、尺寸与场景层级

### 4.1 坐标规则

- 世界以“格”为逻辑编辑单元；全局口径为 `32 像素 = 1 单元格 = 3.2 米`。游戏配置与界面仅使用米，不提供厘米单位。
- 图块素材的源单元为 32×32 像素；战场运行时按同一基准格尺寸缩放绘制，素材像素、逻辑格与世界距离通过统一常量换算。
- 图块、地形和普通物体使用左上角格坐标。
- 单位使用几何中心坐标；单位贴图中心、碰撞中心和关卡实例中心统一。
- 路线节点使用世界坐标并按单位中心移动。
- 场景画布在关卡几何中心所在的单元格内常驻显示“中心”文字。奇数尺寸取唯一中心格；偶数尺寸取四个中心格中的右下格。
- 地图宽度下限为 20 格，高度下限为 12 格。调整尺寸只改变当前战场边界，不移动、裁剪或删除任何层的已有内容；缩小后越界内容暂时保留在草稿中，重新扩大边界时仍可恢复显示。

### 4.2 四个编辑层

1. 底图层：铺设独立图块或 Autotile，构成基础地面。
2. 装饰层：铺设独立图块或 Autotile，用于丰富底图；不承担对象逻辑。
3. 地形层：放置带地形效果的地形实例。
4. 对象层：放置物体、单位和事件区域，并维护独立任务页。

物体和单位拥有 1–5 显示层级。绘制顺序依次比较显示层级、Y 坐标、X 坐标；完全同位时单位显示在物体上方。级别越高越晚绘制。

## 5. 素材与图块

### 5.1 素材库分类

关卡编辑器使用以下相关分类：

- 图块；
- 物体贴图；
- 任务贴图；
- BGM（背景音乐）；
- SE（音效）。

BGM 与 SE 支持 MP3、WAV、OGG。关卡 BGM 下拉框读取 BGM 分类；各音效选择框读取全部 SE 分类，并分组显示内置与已上传素材。图片不能转入音频分类，音频只能在 BGM 与 SE 之间调整。上传音频正文保存到 IndexedDB，素材库的轻量元数据保存在现有素材索引中，避免大型音乐占满 `localStorage`。

素材库中的每条音频提供“试听/停止”：BGM 循环试听，SE 单次试听，同一时间只播放一个条目；切换条目、删除正在试听的素材或离开素材库时自动停止。这里播放原始文件，不叠加后续声音预设的音量、音高或空间处理。

### 5.2 独立图块

- 素材尺寸固定为 160×160 像素。
- 横纵各切为 5 格，共 25 个 32×32 图块，保留原始索引 0–24。
- 全透明单元格不计入有效图块，也不在选择器中显示；有效索引不重新编号。
- 独立图块支持左右翻转和顺时针 90° 旋转。

### 5.3 Autotile

- 静态 Autotile：96×128 像素。
- 动态 Autotile：384×128 像素，横向四帧。
- 邻接拼接遵循 RMXP Autotile 规则。
- 索引使用素材中按 32×32 切分后的第三格作为代表图。
- Autotile 的实际子块由上下左右及角落邻接关系自动计算，不由用户逐块选择。
- 编辑器和游戏场景均不为 Autotile 单元额外绘制黑框。

### 5.4 图块选择器

底图层和装饰层的右侧面板从上到下显示：独立图块、静态 Autotile、动态 Autotile。所有索引格均以 32×32 像素显示，只在当前选中索引格上绘制红色边框。

## 6. 工具栏与场景交互

### 6.1 通用工具

- 保存：保存当前关卡草稿。
- 撤销/重做：作用于完整关卡编辑器。
- 底图层/装饰层/地形层/对象层：切换当前编辑层。
- 显示/隐藏网格：唯一的全局显示开关。

被选中的层级、工具或开关使用明确的选中状态。

### 6.2 图块工具

- 画笔：底图层、装饰层可用；点击放置，按住拖动连续铺设。
- 擦除：底图层、装饰层可用；删除经过地格上的当前层图块。
- 填充：底图层、装饰层可用；按上下左右四连通区域替换相同图块。
- 选择：底图层、装饰层可用；单击选中一个地格，按住拖拽生成吸附完整地格的矩形选区。选区只属于当前层，切换层级后自动清除。
- 选区操作：已有地格选区时点击“擦除”会整块清除当前层图块，点击“填充”会用当前图块整块覆盖；Delete 与整块擦除行为一致。无选区时，擦除和填充仍保持原有逐格/四连通工具行为。
- 翻转：对选中的独立图块，或对象层中选中的物体、单位实例执行左右镜像。
- 旋转：对选中的独立图块，或对象层中选中的物体、单位实例执行顺时针 90° 旋转。

画笔启用时，鼠标绿色定位框内显示当前图块的半透明预览。

### 6.3 地形与对象工具

- 放置：地形层或对象层可用，在绿色定位框处显示并放置当前地形、物体或单位预览。
- 选择：单击只选中并让右侧面板定位实例，不进入幽灵状态；从对象层空白处按住拖动会绘制选择框，所有与选择框相交的物体和单位进入多选。直接按住单个实例约 180ms 或拖过阈值仍进入幽灵状态，松手完成移动。
- 多选结果：右侧显示全部选中实例列表，列表上方提供「只选单位」「只选物体」两个筛选按钮；点击列表条目会切换至该实例所属页并显示具体对象详情，同时保留整组选择。
- 复制/黏贴：支持地形、物体和单位；多选时复制、Delete 删除和黏贴均作用于整组。黏贴后整组副本保持相对位置进入幽灵状态并吸附鼠标，可连续放置，右键或 Esc 退出。事件不支持复制或黏贴。
- 对齐：开启时放置、移动和黏贴吸附地格；关闭后对象可自由定位。路线节点始终按自身规则吸附。
- 擦除：统一承担对象删除功能，不再保留单独“删除对象”工具。
- 起点：对象层可用，设置玩家战车出生区域；关卡始终保留合法起点。
- 事件：切换到事件页并绘制不规则事件区域。

Esc 取消幽灵或清除选中，Delete 删除当前选中实例。取消双击操作概念。按住鼠标中键可平移场景；触摸屏按住拖动可平移，双指可缩放。

物体与单位在选中、拖动幽灵或连续黏贴状态下均可翻转、旋转。单位旋转到 90°/270° 时，占格宽高随实例方向交换；运行时以该角度作为静止初始朝向，镜像载具的车体、履带/轮胎、炮位坐标和射界保持一致。

## 7. 地形与物体类型

### 7.1 地形

地形类型包含名称、Autotile 素材和地形效果。

- 地形贴图使用图块分类中的静态或动态 Autotile。
- 最小单位固定为 1×1 格，不提供默认占格设置。
- 没有贴图时统一回退为白色。
- 地形效果默认为“无效果”；当前已实现移动倍率。
- 地形实例记录类型 ID、位置和当前效果参数。

### 7.2 物体

物体类型包含：

- 名称与物体贴图；
- 普通贴图占格；
- 耐久；
- 阻挡移动；
- 阻挡弹道及高度；
- 显示层级；
- 可用状态列表；
- 物体局部事件。

物体贴图锚定素材库“物体贴图”分类。程序按尺寸判断贴图是否为静态/动态 Autotile：

- Autotile 物体固定为 1×1 占格，场景按相邻同类型物体自动拼接，占格不可修改。
- 普通贴图需要手动设置占格。
- 没有贴图时回退颜色固定为 RGB(83,135,200)。
- 耐久为空或等于 0 表示不可破坏；新建物体默认耐久 0、碰撞关闭、高度 0。
- 高度为 0–3 的离散等级，只在“阻挡弹道”开启时生效。高度参数名悬浮提示完整展示以下规则：高度 0 不遮蔽；高度 1 为普通掩体，阻挡“子弹”直射；高度 2、3 阻挡全部直射子类、射线和喷射。
- 直射弹丸细分为“子弹、穿甲弹、破片弹”，该子类只表达与场景高度的交互，不在此处增加伤害等战斗参数。
- 爆炸经过挡弹道物体到达目标时，取路径上最高遮蔽物计算减伤，不累加：高度 0/1/2/3 分别减伤 0%/30%/60%/80%。
- 工具栏最右侧提供固定的“高度”开关。开启后无需选中实例，画布直接对全部有效遮蔽物着色：高度 1 黄、高度 2 橙、高度 3 红，并显示等级数字；关闭后恢复普通场景显示。

物体实例可以单独调整显示层级、状态、左右翻转和 90° 旋转。

### 7.3 物体事件

物体类型保存“默认事件模板”；放置新物体时把模板复制到关卡实例，之后每个实例独立保存和编辑自己的事件，不再让类型定义长期引用某一关的单位、物体或任务阶段。触发方式限定为：

- 气泡按钮；
- 物体摧毁；
- 接触物体，包括碰撞。

气泡按钮在玩家控制对象距离物体外轮廓 3 格以内时显示，点击该物体触发。每个局部事件拥有名称、触发次数、冷却、条件组和动作序列。物体事件动作可将“事件来源物体”作为目标；单位事件同理可引用“事件来源单位”。物体不再使用行为原型。

## 8. 单位实例

### 8.1 数据归属

关卡单位实例引用统一单位库 ID，不复制单位模板属性。单位模板决定外观、生命、装甲、速度、武器/炮塔和组合式 AI；关卡实例决定位置、阵营、控制器、显示层级、移动行为、路线及局部事件。

关卡编辑器单位面板的索引截图以单位编辑器的外观预览为唯一口径，不另做只显示主体的简化图。载具与飞行平台组合显示载具素材、履带/轮胎、旋翼、涂装、徽记及未隐藏的预装炮塔；普通单位显示单位编辑器默认的移动状态。索引格只负责等比缩放和裁切。

### 8.2 阵营

- 玩家：玩家当前控制单位。
- 友方：与玩家同盟。
- 敌方：与玩家和友方敌对。
- 中立：不主动与其他阵营敌对。
- 中立敌对：与玩家、友方、敌方均敌对；同属中立敌对的单位之间不互相攻击。

所有阵营共用同一份索敌、炮塔、弹丸、受击、装甲、跳弹、爆炸和毁灭逻辑，不为敌我分别实现战斗分支。

### 8.3 控制器

- 玩家控制；
- AI；
- 脚本；
- 静止。

控制器属于关卡实例。单位编辑器不设置阵营，也不决定某个实例由谁控制。

### 8.4 移动行为

- 停留：停在当前位置，不主动移动；脱战后以当前停留位置继续等待。
- 坚守：平时固定在初始位置；接战后允许追击，脱战后通过地格导航返回初始位置，并恢复初始朝向。
- 随机：在放置点周围的指定范围内移动；单次距离取范围的 20%–50%，抵达后按移动间隔重新选点，速度为单位最大速度的百分比。
- 路线：节点按放置顺序自动编号 1、2、3……；依次到达最大编号后等待循环间隔，再返回 1 号节点循环。可编辑、删除或清空节点。
- 接近：玩家进入触发范围后，单位持续向玩家当前位置移动，直到碰撞外沿接触；速度为单位最大速度的百分比。
- 跟随：单位持续跟随玩家，并保持可配置的外沿间距；速度为单位最大速度的百分比。该实例行为对友方、敌方等全部阵营使用同一套规则。

移动行为只接管移动决策，攻击仍由单位模板的共用战斗逻辑处理。地面单位的坚守归位、随机、路线、接近和跟随统一使用地格导航；飞行单位继续直达目标并忽略地面阻挡。随机目标只会从当前实际可达区域中选择，路线节点不可因不可达而跳过。

导航只提供可达方向和前视路点，最终移动仍使用单位模板对应底盘的加速度、转向半径、碰撞、地形倍率和实体分离。转弯半径为 `0` 的履带载具可原地转向；大于 `0` 时导航不会绕过其转向限制。

同一单位通行轮廓、同一目标格和同一地图阻挡版本共享距离场，不让每个单位单独运行完整寻路。移动目标每 `0.25 秒` 或跨格时更新；单位持续约 `0.65 秒` 没有产生有效位移或转向进展时触发脱困重算。静态障碍变化会通过地图阻挡版本使缓存失效；其他移动单位不写入静态路径场，仍交由运行时实体分离处理。

### 8.5 单位事件

单位实例可添加局部事件，触发方式为气泡按钮、单位摧毁或接触单位。结构与物体局部事件一致，均包含次数、冷却、条件和动作。气泡按钮同样使用 3 格外轮廓距离。

## 9. 统一事件系统

### 9.1 事件结构

独立关卡事件包含：稳定 ID、名称、启用状态、触发次数、冷却、触发方式、条件组和有序动作序列。次数为 0 表示无限。

事件区域是任意地格集合，可以是不规则、镂空或互不相连的形状，不强制为矩形。区域事件生成单位或 Boss 时也严格从实际选中的地格中取点，不使用区域包围盒中的空洞。

### 9.2 触发方式

独立事件页当前提供：

- 任务开始；
- 自动；
- 并行；
- 阶段成功；
- 阶段失败；
- 进入区域；
- 离开区域；
- 停留区域。

物体或单位相关的气泡、接触和摧毁触发保存在各自局部事件中，不在独立事件触发方式里重复出现。原“交互物”功能已经并入局部事件与动作序列。

### 9.3 条件

独立事件、物体事件、单位事件和任务简报目标共用一个条件编辑器。条件组支持“全部满足”和“任一满足”，可添加多条：

- 单位死亡/存活；
- 物体摧毁/未摧毁；
- 物体状态等于/不等于指定状态；
- 任务胜利；
- 玩家战车结构值；
- 敌方载具存活数；
- 击杀数；
- 当前波次；
- 任务时间；
- 关卡变量；
- 全局变量。

数值与变量比较支持等于、不等于、大于、不小于、小于、不大于。

### 9.4 变量

- 关卡变量仅属于当前关卡，统一为数值变量。
- 全局变量属于整个关卡库，同样统一为数值变量；当前值保存在玩家进度中，可跨关卡读取。
- 旧布尔变量在读取时自动迁移：`true → 1`，`false → 0`。
- 设置/增减变量动作可以自动创建变量定义；事件页集中显示并允许改名、设置初始数值或删除。

### 9.5 动作序列

事件动作按顺序执行，当前动作类型包括：

- 等待；
- 生成普通敌群或单位；
- 生成 Boss 及生命阶段/击败动作；
- 显示任务消息；
- 镜头转移；可设置移动时间与停留时间，勾选“返回”后会在停留结束时按相同移动时间回到转移前的镜头位置；
- 发放资源奖励；
- 切换当前阶段目标；
- 设置或增减关卡变量、全局变量；
- 启用或禁用其他事件；
- 调用其他独立事件；调用方默认等待被调用事件动作执行完毕后继续，保留当前事件来源单位、来源物体和区域上下文，递归调用最多 8 层；
- 修改物体状态；
- 增减资源、弹药和能量；
- 功能区域：应配合“停留区域”触发方式使用，可同时勾选一个或多个功能。补充弹药按每座炮塔的弹药汇率换算后钳制到自身容量；充能恢复炮塔能量；修理分别配置结构与四向装甲的每秒恢复量；整备允许在区域内打开炮塔、模块更换界面。离开区域后所有功能立即停止。战场按实际功能绘制区域外轮廓并显示状态，重叠功能区域的补充、充能和修理效率相加；
- 旧动作 `supplyZone` 在读取时自动迁移为“功能区域”，仅保留其原有补充弹药/充能能力；不再向新关卡写入旧动作名。旧的独立装配区域继续兼容读取；未配置任何整备区域的旧关卡仍以起点作为兼容整备区；
- 判定任务胜利或失败；
- 完成次要目标；
- 单位指令在指令列表中独立归入“单位”分类，包括移动、飞行高度、停留、攻击、AI 控制、移除和变更行为；
- “飞行高度”填写目标高度（格），运行时按单位模板的最低/最高高度自动钳制；可勾选等待到达。非飞行单位不会改变，也不会阻塞事件序列；
- 攻击指令可指定玩家、关卡单位实例或物体对象；Autotile 连通物体按一个对象目标处理；
- 变更行为可切换静止、随机、路线、接近、跟随，或恢复关卡实例的初始行为；
- 完成当前动作流程。

等待动作会阻塞当前序列；单位指令可选择是否等待完成。不同事件实例可以并行运行。同一个“并行”或“停留区域”事件默认禁止动作序列重入：前一轮未结束时，即使冷却为 0 也不会重复排队。

事件监视器在战斗中显示最近触发记录、自动触发次数、直接调用次数、当前动作、等待原因和完成记录；相同的持续阻塞原因只记录一次，避免逐帧刷屏。

保存关卡前执行跨引用检查：空事件区域、失效的任务阶段/事件/物体/单位引用、空变量名、无动作事件、已删除素材或声音，以及事件自操作和调用循环。对象层中的物体、单位及路线、事件区域、玩家起点或任务终点只要仍有部分位于战场边界外，就作为错误阻止保存并提供定位入口。若对象层没有越界错误，保存时自动删除边界外的底图格、装饰格和旧地面格；越界或部分越界的地形实例按整个实例删除，不静默裁剪占格。其他错误阻止保存，警告在校验面板中提示。

## 10. 独立任务页

任务页维护关卡的阶段流程，不与事件页合并。每个关卡至少有一个任务阶段，并指定一个起始阶段。

### 10.1 阶段类型

- 防守：保护指定物体或单位，并配置波次。
- 堡垒防御：在指定位置临时接管关卡指定堡垒，抵挡从关卡编号出生区域出现的波次，并在准备阶段整备关卡中预先放置的玩家单位。
- 生存：坚持指定秒数。
- 抵达：玩家进入本阶段的不规则终点地格集合。
- 护送：保护并护送指定非敌方单位实例。
- 摧毁：摧毁一个或多个指定敌方单位实例。

玩家当前控制单位彻底毁灭仍按全局失败规则结束任务；堡垒防御阶段中被接管堡垒就是玩家控制单位。

### 10.2 阶段流转

每个阶段分别配置成功后和失败后的去向：

- 进入另一阶段；
- 整关胜利；
- 整关失败。

阶段成功/失败也可以作为独立事件触发方式，使演出、奖励、变量和场景变化与任务流转组合。

任务阶段允许跳回已执行过的阶段。普通重入会清除该阶段上一轮的成功/失败标记；同阶段自循环会先保留本轮结果脉冲供阶段事件消费，并重置事件边沿状态，使对应阶段事件能够每轮再次触发。

### 10.3 防守波次

防守阶段包含有序波次，每波包含一个或多个单位编队。编队配置单位库引用、数量、开始延迟、单位间隔和出生区域选择。

每个波次单独配置“敌人强度系数”，默认 `1`。该值是本波敌人全部攻击伤害的倍率，会随敌人传递到其发射的弹丸、射线、喷射和爆炸等伤害来源；`1.5` 表示造成正常值的 150%，不改变敌人的结构值、装甲、移动、射速或弹丸速度。

- 清场等待模式：当前波敌人和相关队列清空后进入休整，再开始下一波。
- 接踵模式：最后一个编队开始出场后按接踵时间启动下一波，不等待上一波全部消灭。
- 首波按照当前模式进入部署倒计时或直接开战。
- 防守和堡垒防御阶段只要存在正在运行的首波部署、波间休整或接踵倒计时，战斗 HUD 正上方居中显示 `下波进攻倒计时：MM:SS`；最后一波结束、非防守阶段和胜负结算不显示。暂停战斗时直接冻结现有引擎倒计时，不另建 UI 计时器。
- 防守和堡垒防御阶段各自维护一组稳定编号的敌人出生区域。区域在任务页中新建并直接于场景画布自由绘制，可形成不规则形状；同一格只归属一个区域，区域显示最外围轮廓和编号。
- 每个波次编队可选择“随机”或指定区域编号。指定时，该编队全部单位从对应区域的随机格生成；随机时，每个单位分别从当前阶段的非空区域中随机选择，再从该区域随机选择一个格生成。
- 删除区域时，引用它的波次编队自动恢复为“随机”。空区域、越界区域、重复编号和失效引用都会在保存检查中阻止保存。
- v17 及更早关卡的上、右、下、左出生方向在读取时迁移为一格宽的边缘编号区域；旧防守默认迁移上边缘，旧堡垒防御默认迁移四边缘。

### 10.4 堡垒防御阶段

- 关卡配置堡垒单位、堡垒几何中心和玩家载具返回点。任务页选中堡垒防御阶段时，战场画布直接渲染堡垒单位和“返回位置”标识，两者均可拖拽并受对齐模式影响；右侧坐标输入用于精确调整。所有拖拽纳入编辑器撤销/重做，保存检查拦截越界配置。
- 固定火力点不再使用独立“固定炮塔槽位”。设计者改在对象层放置阵营为“玩家”的单位，并按需勾选“锁定移动”和“锁定车体转向”。两项锁定只限制单位底盘，炮塔仍按统一索敌和开火逻辑工作；需要固定炮台底座时应同时勾选两项。
- 进入阶段时完整暂存玩家当前载具状态、已装炮塔和模块；不保存朝向。玩家载具暂时隐藏，指定堡垒在关卡坐标出现并成为当前玩家单位，移动输入不会使其位移。
- 波次准备阶段可点击任意存活的玩家单位打开炮塔整备。该入口只允许安装、拆除和替换该单位炮位中的炮塔，不开放该单位的独立模块面板；除主控单位外的玩家单位统一共享主控单位已经安装的模块效果。炮塔尺寸和类型仍须匹配对应炮位。
- 所有玩家单位均按主控单位的资源口径维护每座炮塔自己的弹药和能量；初始预装炮塔默认允许替换。单位编辑器可对具体预装炮位勾选“锁定炮塔”，锁定后仍可战斗、补给和维修，但不可在整备中拆除或替换。
- 堡垒防御整备只在波次准备阶段开放，统一消耗关卡资源，不受关卡装配分上限限制。新装炮塔获得满额初始弹药和能量；替换或拆除时按现行资源规则结算，预装炮塔本身不产生免费拆卸返款。
- 阶段成功或跳转离开时，玩家原载具在返回点恢复、朝向重置为默认方向，先前炮塔和模块恢复。存活堡垒转为普通友方单位，之后被摧毁不再导致任务失败；其他玩家单位及其当前炮塔永久留在场景中。
- 若堡垒阶段失败分支跳往其他任务阶段，同样执行上述退出流程；若失败去向为整关失败，则按关卡失败结算。

## 11. 关卡信息、任务目标与进度

### 11.1 关卡信息

左侧“关卡信息”维护：

- 关卡名称；
- 战场宽、高；
- BGM；
- 任务贴图；
- 任务简报；
- 1 个主要目标和 2 个次要目标；
- 备选出战车辆；
- 下一关；
- 资源奖励；
- 装备解锁奖励：可选择战车、炮塔、模块和徽记。

任务贴图锚定“任务贴图”素材分类；关卡列表本身不显示图片。

### 11.2 目标状态来源

关卡信息只编辑主要目标和两个次要目标的显示文字，不设置完成规则、判断条件或判定方式。目标状态只有两个来源：

- 事件动作“任务结果”；
- 任务阶段的最终成功或失败去向。

主要目标完成后立即结束关卡并进入胜利，主要目标失败后立即进入失败。次要目标由事件动作设为完成，达成后立即反映在战斗 HUD 中；最终结算只有在整关胜利时才确认已经达成的次要目标并发放对应勋章，关卡失败时所有目标均不作为最终完成结果。

### 11.3 战斗 HUD 与结算

- 战斗主界面左上角先显示玩家战车结构/护盾叠加条及热量条，下方显示主要目标和两个次要目标；结构状态区同时保留速度、资源和四向装甲摘要。
- 次要目标左侧为只读勾选框；完成后自动勾选并将文字置灰。
- 右下角按当前已安装炮塔生成独立自动开火按钮：按钮包含类型图标、炮塔名称、开关状态和该炮塔自身的弹药/能量竖条；旧的全局弹药、全局能量 HUD 不再显示。
- 任务完成界面冻结任务用时，显示结果、用时、击杀数、出战车辆和三个目标，不显示结构剩余或车辆状态。
- 每个目标对应一枚勋章；已经获得的勋章需要明确标记，重复挑战不重复记录。
- 首次胜利发放装备解锁奖励，资源奖励仍按现行规则发放，并解锁后续关卡；失败不发放通关奖励。
- 装备所有权永久保存在玩家进度中，同时记录关卡或成就商店来源；重复通关、重复购买不会重复写入。

### 11.4 关卡任务界面

进入战斗前使用全屏“关卡任务”界面：

- 左侧为无缩略图的关卡列表，未解锁关卡不可点击；
- 中间显示任务贴图和出战车辆选择；
- 右侧显示任务简报、主要目标和两个次要目标；
- 底部提供返回与开始任务。

出战车辆显示名称和完整合成预览，车头朝上；优先按素材原尺寸 1:1 显示，超出区域时整体等比缩小。预览必须包含底座、履带/轮胎、主体及预装炮塔。

关卡可配置备选车辆白名单；旧关卡未配置时允许单位库中全部合法玩家载具。白名单只决定本关允许出战的范围，玩家仍须已经拥有该车辆；未解锁车辆保留展示并标记锁定，但不可选择。

### 11.5 战车整备与出战预设

- “关卡任务”界面提供全屏战车整备入口；关卡界面只选择已经保存的出战预设，不在任务界面内直接装配。
- 每份预设绑定一个载具定义，并保存稳定预设 ID、名称、普通炮位的预装炮塔，以及内部模块的位置和旋转状态。每种载具至少保留一份预设。
- 左侧只显示玩家已经解锁的车型；同车型的多份出战方案在预览上方的方案选择框中管理。由关卡任务界面进入整备时锁定当前出战车型，其他已解锁车型保留显示但不可切换；非关卡入口可以在已解锁车型间切换。
- 中央显示载具完整合成预览、炮位与模块列表；右侧装备仓库按炮塔和模块分类，并且只列出玩家已经解锁获得的装备。未获得装备不出现在仓库中；已获得但与当前炮位不兼容或内部空间不足的装备不可安装，并显示原因。
- 参数区只显示当前方案的结构、护盾、四向装甲总值、速度、转向、单轮火力、资源上限和散热；草稿相对已保存预设发生变化时，在当前参数值后追加带正负号的变化量，不再并列显示两套参数。
- 保存预设后才正式提交装配并设为当前出战方案。进入关卡时，预装炮塔和模块转换为现有炮塔、模块运行时实例，复用同一战斗、受击、资源和生产逻辑，不建立整备专属战斗分支。
- 关卡出战白名单约束预设所属载具；载具或预设中的任一炮塔、模块未解锁时，该预设不可用于开始任务。
- 每个关卡在“关卡信息”中配置 `assemblyPointLimit`（装配分上限，默认 30）。炮塔和模块分别配置自己的装配分；旧装备未填写时按造价每 50 资源约 1 分自动换算，至少 1 分，显式填写 0 可作为免费装备。
- 战斗主界面的“整备”按钮打开覆盖于战场下方的轻量浮动 HUD，不再复用全屏整备页。打开后战场仍保持大面积可见；HUD 标题栏显示当前单位、整备模式和装配分/资源摘要，主体只显示当前单位预览、已装炮塔/模块和已解锁装备仓库，隐藏车型列表、预设新建/删除与名称编辑。战斗整备锁定当前车型，只允许使用玩家已经解锁的炮塔和模块；当前总装配分不得超过本关上限。
- 战斗整备以当前运行中的实际装备生成临时草稿。初始预装炮塔和模块也进入草稿，默认都能卸下或替换；只有单位炮位显式勾选“锁定炮塔”时，对应预装炮塔不可拆换。
- 点击“应用整备”后一次性替换当前战车装备，不改写玩家保存的出战预设；点击返回则丢弃草稿。相同炮位上的同定义炮塔和未变更模块尽量保留运行状态，避免单纯打开界面刷新冷却或生产计时。
- 单人模式打开战斗整备时暂停逻辑帧、任务计时和移动输入；关闭或应用后继续战斗。未来多人模式不得以本地全局暂停实现，应由多人规则另行决定整备时机。
- 堡垒防御下复用同一浮动 HUD：主控单位可调整炮塔与模块，以关卡资源显示本次整备消耗；其他玩家单位只显示炮塔装配，模块沿用主控单位配置。矮屏横屏隐藏重复的单位预览，仅保留标题中的单位名、已装装备和可用装备；竖屏改为上下分区，保证触屏按钮可操作。

### 11.6 勋章与成就商店

- 每个关卡的一项主要目标和两项次要目标各对应一枚永久勋章；同一目标重复完成不会重复获得。
- 可用勋章 = 累计获得勋章 − 已消费勋章。消费记录写入玩家进度，不受重复挑战或切换关卡影响。
- “关卡任务”界面提供独立成就商店入口；商店按装备类别筛选，显示累计、已消费和当前可用勋章。
- 首批商品由稳定目录配置，包含商品 ID、显示名称、说明、勋章价格和装备引用。目录装备在解锁前会同步锁定战斗中的建造或选择入口。
- 兑换成功后原子写入勋章消费、永久装备所有权与商店来源记录；勋章不足时不产生任何写入，重复兑换不会再次扣费。
- 同一装备允许配置为关卡通关奖励。若已通过关卡奖励获得，商店显示其来源并视为已解锁，无须也无法重复兑换。
- 当前目录先提供炮塔与模块奖励；数据协议保留战车、涂装和徽记类别，后续只需扩充商品配置及对应预览，不修改所有权协议。

战斗中的炮塔和模块装配同样读取统一装备所有权。没有被任何关卡奖励或商店商品登记的现有装备默认可用，避免旧项目升级后被意外锁定；一旦装备进入解锁目录，则任意一个来源成功解锁后永久拥有。

## 12. 保存、迁移与兼容边界

- 关卡库、关卡进度、地形/物体类型库和素材库分别持久化，但通过稳定 ID 相互引用。
- BGM 与 SE 正文保存在 IndexedDB，统一音频管理器负责解码缓存、主音量/BGM/SE 总线、首次交互解锁、暂停恢复与实例循环声；编辑器不得绕过管理器直接创建播放实例。
- BGM 配置分为两级：关卡选择（含任务介绍）、胜利结算、失败结算各使用一首全局唯一曲目，由统一音频设置配置；关卡战斗 BGM 则保存在各关卡基础设置中，因此不同关卡可以使用不同音乐。Boss 或剧情事件可临时覆盖战斗 BGM，覆盖结束后恢复当前关卡曲目。
- SE 选择框只显示“未配置”以及按“内置/已上传”分组的音效素材，不显示“无”或声音预设。选择后由后台生成只含一个素材的声音配置；选择框右侧的参数按钮可在小窗中调整当前音效的音量、音高范围、冷却、并发和传播距离，但不允许增减素材或改动自动通道与循环方式。参数小窗提供“播放/停止”按钮，使用当前音量和音高范围试听；循环类音效持续播放到手动停止或关闭窗口。
- 后台按使用位置自动分配声音通道与播放参数：炮塔和弹丸使用武器通道，单位面板使用单位通道，UI 点击等界面声音使用 UI 通道，物体与关卡事件使用环境通道；移动、弹丸飞行和射线持续音效自动启用循环。
- 全局通用声音只覆盖 UI、任务、护盾、移动类型、单位毁灭、物体交互和碰撞等跨对象事件。装甲穿透、物体摧毁、炮塔动作、弹丸飞行/命中/跳弹及通用爆炸不设置全局回退。炮塔音效集中在炮塔参数下方；射线炮塔额外配置充能与装填。弹丸的飞行、命中、跳弹、爆炸音效默认均未配置，射线弹丸可配置持续攻击循环音效。
- 事件动作支持“播放音效”和“切换 BGM”；临时 BGM 可由后续“恢复关卡 BGM”动作结束。音频事件只消费战斗表现数据，不参与伤害、物理和确定性模拟。
- DEBUG 编辑器设有独立“游戏参数”切页。“战斗参数”中的“自然散热值”（0~1000 点/s）控制玩家当前战车的基础自然散热，散热模块在其上额外叠加，且热量上限变化不会联动调整该值或炮塔产热。“画面设置”可持久化主界面的默认、最小和最大缩放比例，默认值始终被钳制在最小/最大范围内；滚轮与双指缩放共用该边界。音频设置从素材库迁移至画面设置面板下方。
- 读取时统一归一化非法尺寸、重复 ID、失效关卡链、越界坐标、坏变量和失效单位引用。
- 旧矩形伏击和旧交互物在读取时迁移为统一事件。
- 旧初始炮塔字段读取后丢弃。
- 旧核心、固定建筑和独立墙体字段只保留底层读取兼容；进入新版关卡编辑器后清空，不再显示、创建、选择或绘制。
- 旧地面字段迁移到现行底图/装饰图块协议。
- 当前关卡配置仍保留必要的旧字段用于向前读取，不代表这些字段仍属于产品设计。

## 13. 运行时一致性原则

- 编辑器预览与游戏场景读取同一套图块、Autotile、物体和单位绘制数据。
- 关卡单位引用统一单位库，关卡不复制单位战斗参数。
- 所有阵营共用敌对关系、移动、碰撞、索敌、炮塔、弹丸和承伤系统。
- 关卡事件和单位/物体局部事件共用同一条件判断入口；目标状态不建立独立条件系统。
- 事件动作、Boss 阶段动作和单位局部事件共用同一动作协议。
- 任务阶段决定任务状态机，事件只监听或影响状态，不建立第二套任务流程。

## 14. 验收基线

每次修改关卡编辑器至少验证：

1. TypeScript 类型检查通过。
2. 关卡库新建、复制、删除、排序、保存和重新载入正确。
3. 四层放置、擦除、填充、选择、移动、复制/黏贴及撤销/重做正确。
4. 独立图块透明格过滤与静态/动态 Autotile 邻接正确。
5. 地形效果、物体碰撞/耐久/状态和局部事件正确。
6. 五种阵营、控制器和五种移动行为按实例配置生效。
7. 事件触发、组合条件、变量和动作顺序正确，事件不可复制/黏贴。
8. 六类任务阶段、成功/失败分支、波次、编号出生区域与随机/指定区域生成、堡垒切换/返回点、玩家固定火力单位及终点区域正确。
9. 简报目标、HUD 勾选、结算勋章、奖励、解锁和下一关正确。
10. 正式构建成功；构建包拆分警告按《待开发记录》中的性能项单独处理。
