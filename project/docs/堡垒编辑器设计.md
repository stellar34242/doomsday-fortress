# 堡垒编辑器设计 · 第 1~3 章

> 坐标约定（全文通用）：堡垒局部坐标原点为包围盒左上角，x 向右、y 向下（船头朝 −y 方向）；船头朝向 `heading` 为弧度，0 = 朝屏幕上方，顺时针为正，方向向量 `(dirX, dirY) = (sin h, −cos h)`。长度单位为格（1 格 = 25 m，`M_PER_CELL = 25`），基准像素 30 px = 1 格（`BASE_CELL = 30`）。

## 1. 总览与堡垒数据结构

### 1.1 堡垒域范围

堡垒（Fortress）是玩家驾驶的**可移动载具 + 炮塔载体**：它在战场上以连续坐标平移/转向，船体血量归零即判负；炮位上挂载的炮塔随船体联动。堡垒编辑器编辑的是**堡垒类型定义 `FortressDef`**（"这型堡垒长什么样"），而非局内运行时状态。堡垒域覆盖五块：

| 子域 | 内容 | 对应字段/机制 |
| --- | --- | --- |
| 船体 | 包围盒、自由网格形状（碰撞体）、底座/主体贴图、颜色、船体血量 | `w/h`、`shape`、`spriteBase/spriteBody`、`color`、`hp` |
| 机动 | 速度/加速度、双底盘转向（履带差速 / 轮式前轮转向）、弧线覆盖、倒退、刹停、俯仰悬挂 | `speed`、`accel`、`turnSpeed`、`turnRadius`、`chassis` 及底盘参数组、`reverseFactor`、`brakeInertia`、`pitchGain/leanCap`（见第 2 章） |
| 炮位 | 挂点坐标、型号（S/M/L）、射界/固定视角、类型限制、隐藏内置、渲染层级 | `hardpoints: Hardpoint[]` |
| 内部空间 | 模块摆放格阵（矩形或自由格阵）、特殊格加成 | `interior`、`interiorCells`、`interiorSpecials` |
| 热量 | 全炮塔产热汇聚池，攒满过热停火；自然散热 + 散热器模块叠加 | `heatCap`、`heatDissipation` |

堡垒还携带三类纯视觉美术组：**履带**（`tracks`，瓦片循环滚动 + 落印）、**轮子**（`wheels`，与履带独立共存，半履带 = 前 wheels + 后 tracks）、**特效点**（`effects`，贴附船体的程序化粒子发射点）。三者均不参与碰撞与数值。

### 1.2 FortressDef 参数全集

类型定义见 `src/game/config.ts`（`interface FortressDef` / `TrackDef` / `WheelDef` / `Hardpoint` / `FortressEffectPoint`），取值范围以 `src/game/engine.ts` 的 `validateFortressDef` 校验闸为准（编辑器保存/导入时强校验，非法即拒绝）。

#### 1.2.1 标识 · 几何 · 贴图

| 参数 | 中文 | 类型 | 默认值 | 取值范围 | 现行语义 |
| --- | --- | --- | --- | --- | --- |
| `id` | 类型 id | string | — | 定义内唯一 | 自定义堡垒以 `custom-` 前缀与内置命名空间隔离 |
| `name` | 名称 | string | — | — | 类型库显示名 |
| `w` | 包围盒横向格数 | number（整数） | — | 1~30（仅未配置 `shape` 时强制；有 shape 时按形状包围盒、不设上限） | x 向格数；配置 `shape` 时须等于形状包围盒宽（编辑器保存时自动重算） |
| `h` | 包围盒纵向格数 | number（整数） | — | 1~18（同上：仅无 shape 时强制） | y 向格数（船头纵轴方向）；配置 `shape` 时须等于形状包围盒高 |
| `shape` | 自由网格形状 | string[]（"x,y"） | 未配置 = w×h 满矩形 | 非空、坐标为非负整数、不重复、4-连通成整体，允许镂空 | **形状格是唯一碰撞体**（寻路目标格/挡敌/挡移动逐格判定）；贴图不参与碰撞 |
| `spriteBase` | 底座贴图 | string | 无（色块） | — | dataURL 或 /res 路径（旧 /sprites 前缀自动兼容——兼容回退）；仅视觉 |
| `spriteBody` | 主体贴图 | string | 无（色块） | — | 同上；仅视觉。内部建造模式下隐藏主体层、露出底座格阵 |
| `color` | 底色 | string | — | — | 无贴图时的堡垒色块颜色 |

#### 1.2.2 内部空间（模块格阵）

| 参数 | 中文 | 类型 | 默认值 | 取值范围 | 现行语义 |
| --- | --- | --- | --- | --- | --- |
| `interior.cols` | 内部空间列数 | number | — | 不得超出 `w` | 内部模块空间编辑网格宽；与底座格 1:1 对齐 |
| `interior.rows` | 内部空间行数 | number | — | 不得超出 `h` | 内部模块空间编辑网格高 |
| `interiorCells` | 内部自由格阵 | string[]（"x,y"） | 未配置 = 左上角锚定 cols×rows 满矩形 | 逐格 ⊆ 形状格集合 | 逐格决定可摆放模块的位置（`canPlaceModule` 逐格校验）；`fortressInteriorSet()`：自由格阵优先，缺省回退 cols×rows 满矩形 |
| `interiorSpecials` | 内部特殊格 | `{x,y,boost}[]` | 无 | 格须在内部空间集合内且不重复 | 模块占格覆盖特殊格 → 对应属性 ×`SPECIAL_MULT`（1.5；生产类 = 产出间隔 ÷1.5）。`boost`：`energy` 电力 / `ammo` 弹药 / `cooling` 散热 / `repair` 维修 / `range` 火控 / `produce` 生产 / `hp` 结构 / `speed` 机动 / `turn` 转向 |

#### 1.2.3 机动与悬挂（数值组）

| 参数 | 中文 | 类型 | 默认值 | 校验范围 | 现行语义 |
| --- | --- | --- | --- | --- | --- |
| `hp` | 船体血量 | number | — | 500~20000 | 船体耐久上限基数；局内上限 = `hp + 模块 hpBoost 池`（`fortressMaxHp`）；归零进入毁灭序列（§1.5），演出毕判负 |
| `speed` | 移动速度 | number（格/s） | — | 0.2~6 | 最大前进速度基数；局内 = `max(0.2, speed + 模块 speedBoost 池)`（`fortressSpeed`） |
| `accel` | 加速度 | number（格/s²） | — | 0.5~20 | 加/减速同率；刹停时乘刹停倍率（见 `brakeInertia`） |
| `turnSpeed` | 转向速度 | number（度/s） | — | 15~240 | **可选横摆角速度上限**：履带 = `min(本值, 2×极速/履带间距)`；轮式 = `min(本值, v·tanδ/轴距)`；弧线模式 = `min(本值, 弧速/半径)`。局内 = `max(10, turnSpeed + 模块 turnBoost 池)`（`fortressTurnSpeed`） |
| `turnRadius` | 最小转弯半径 | number（格） | 0 | 0~20 | >0 时进入两底盘通用的**弧线转向覆盖**：绕外侧圆心走弧、转弯带动前行；0 = 按底盘物理（履带差速 / 轮式前轮角） |
| `reverseFactor` | 倒退系数 | number | 0.8 | 0~1 | 倒退最大速度 = 前进 × 系数，倒退加/减速度同样 × 系数（0.8 = 倒退极速/加速度为前进的 80%） |
| `brakeInertia` | 刹停惯性 | number | 5 | 1~10 | 减速度倍率映射：`i≤5 → 3−(i−1)/2`；`i>5 → 1−(i−5)×0.16`。即 1 = 3×加速度急停，5 = 等于加速度，10 = 0.2×加速度长滑行（`brakeDecelMult`） |
| `pitchGain` | 车身俯仰强度 | number | 4 | 0~10（0 = 关闭） | 汽车悬挂拟真强度：偏移量系数 `k = pitchGain × 0.5` px/(格/s²)，偏移 = 本 tick 实际加速度的反向映射（加速后倾 / 减速前倾 / 弧线侧倾 ×0.4）；仅视觉 |
| `leanCap` | 俯仰位移上限 | number（px） | 4 | 1~8 | 目标倾角钳制值；弹簧过冲软上限 = `leanCap + 1` px |

#### 1.2.4 底盘参数组（`chassis` 及从属参数）

| 参数 | 中文 | 类型 | 默认值 | 校验范围 | 现行语义 |
| --- | --- | --- | --- | --- | --- |
| `chassis` | 底盘类型 | `'tracked' \| 'wheeled'` | `'tracked'` | 仅两枚举值 | 履带差速（静止可原地枢轴转）/ 轮式前轮转向（静止无转向能力） |
| `trackWidth` | 履带间距 | number（格） | `w` | (0, 20]，引擎取用时下钳 0.5 | 【履带】枢轴角速度推导上限 = `2×speed / trackWidth` |
| `turnDrag` | 转向阻力 | number | 0 | 0~0.9 | 【履带】转向输入期间目标速度 ×`(1−turnDrag)`（滑移转向功耗；弧线模式不乘） |
| `wheelbase` | 轴距 | number（格） | `h × 0.6` | (0, 30]，引擎取用时下钳 0.5 | 【轮式】转弯半径 `R = 轴距 / tan(前轮角)` |
| `steerMax` | 最大前轮转角 | number（度） | 35 | (0, 80] | 【轮式】前轮角 δ 的幅值上限 |
| `steerRate` | 方向盘转速 | number（度/s） | 120 | (0, 720] | 【轮式】δ 的积分速率；无输入时以同速率自动回正 |
| `gripMax` | 横向附着上限 | number（m/s²） | 8 | (0, 100] | 【轮式】`v²/R` 超限即压缩有效前轮角：`tanδ_eff ≤ grip·L/max(v², 0.25)`（引擎内经 `m2c` 换算为 格/s²；v<0.5 格/s 不再收紧）；运动学模型无漂移 |

#### 1.2.5 热量

| 参数 | 中文 | 类型 | 默认值 | 校验范围 | 现行语义 |
| --- | --- | --- | --- | --- | --- |
| `heatCap` | 热量上限 | number | — | 50~2000 | 所有炮塔开火产热汇聚于此池，攒满即过热（全炮塔停火）；降至上限 ×`OVERHEAT_RESUME`（0.5）时恢复射击（迟滞） |
| `heatDissipation` | 自然散热 | number（点/s） | — | 1~100 | 持续生效（含射击/过热中）；局内散热速率 = `heatDissipation + 模块散热器冷却池`（`fortressCooling`） |

### 1.4 缺省/可选参数回退约定

| 可选参数 | 未配置时的回退行为 |
| --- | --- |
| `shape` | w×h 满矩形（`fortressShapeSet` 按 0..w−1 × 0..h−1 展开） |
| `interiorCells` | 左上角锚定 cols×rows 满矩形（`fortressInteriorSet`） |
| `interiorSpecials` / `effects` / `tracks` / `wheels` | 无对应层：无特殊格加成 / 无特效粒子 / 无履带动画层 / 无轮子 |
| `chassis` | `'tracked'`（履带底盘） |
| `trackWidth` | `w`（取用时下钳 0.5 格） |
| `turnDrag` | 0（转向不降速） |
| `wheelbase` | `h × 0.6`（取用时下钳 0.5 格） |
| `steerMax` / `steerRate` / `gripMax` | 35° / 120°/s / 8 m/s² |
| `turnRadius` | 0（按底盘物理转向） |
| `reverseFactor` | 0.8（钳 0~1） |
| `brakeInertia` | 5（减速度 = 1×加速度） |
| `pitchGain` | 4；0 = 关闭俯仰并强制回正 |
| `leanCap` | 4 px |

### 1.5 堡垒毁灭序列（v2.53）

船体 hp 归零**不再同帧判负**，进入毁灭演出状态机；演出结束后才切 `phase='lost'`。

**状态字段**：`fortress.dyingT`（-1 = 存活；≥0 = 毁灭演出计时，秒）。归零当帧置 0，每 tick 推进。

**三段式时间轴**（常量见 engine.ts `DEATH_*`）：

| 阶段 | 时刻 | 表现 | 逻辑 |
| --- | --- | --- | --- |
| 内伤连锁 | 0 / 0.25 / 0.55s | 船体格位 3 次小爆（`deathSmall` 爆炸事件，确定性格位选取 20%/50%/80%，不用随机——sim 可复现）+ 船体变暗（0.10→0.45）+ 缓释浓烟 | 操控输入冻结（惯性滑停）、全炮塔停火 |
| 主爆 | 0.8s | 中心大爆炸（`deathMain`，半径 = max(w,h)×0.8 格）+ 船体转焦黑残骸态（0.45→0.75）、炮塔不再绘制、浓烟加浓 | **AOE 伤害 25**，波及半径内敌人与僚机（不分敌我；驾驶员下车被波及的判负联动待驾驶员模式落地） |
| 残骸余烟 | 0.8~2.2s | 残骸 + 余烟 | 到 `DEATH_END_T`（2.2s）切 `phase='lost'`，结算遮罩淡入 |

**设定依据**：
- **判负与毁灭事件解耦**（hp 归零发毁灭事件，是否判负由模式规则决定）——为驾驶员模式预留：未下车随舰亡=判负；已下车且未被主爆 AOE 波及=对局继续。防守模式下恒判负，规则分发点已就位，落地驾驶员模式时不返工。
- 毁灭演出爆炸事件带 `kind` 字段、**不依赖弹丸美术库配置**（固定橙金配色；v2.54 起与弹丸爆炸共用统一画法：火球+软边冲击环+瞬时照明+拉丝火花/烟尘；v2.55 起画法收敛于 `fxDraw.ts` 共用层，战场与编辑器预览同一函数），避免玩家未配置爆炸美术时堡垒"无声消失"。
- 演出期间步骤 9 提前返回：不判胜、不推进波次（即使主爆 AOE 清空场上敌人也不会误判胜）。

## 2. 机动系统

机动模拟在备战/交战两阶段均生效，每 tick 执行：输入 → 目标速度向量 → 加速度趋近 → 俯仰悬挂 → 履带/轮相位 → 轴分离位移 → 转向积分。运行时载体状态：`heading`（船头朝向）、`vx/vy`（速度向量，格/s）、`turnW`（当前转向角速度 rad/s）、`steerAngle`（轮式前轮角 rad；履带底盘恒 0）、`lean*/trackPhase` 等视觉状态。

公用派生函数（均含内部模块加成）：

| 函数 | 表达式 | 语义 |
| --- | --- | --- |
| `fortressSpeed(s)` | `max(0.2, def.speed + speedBoostPool)` | 最大速度 maxSpd（格/s） |
| `fortressTurnSpeed(s)` | `max(10, def.turnSpeed + turnBoostPool)` | 横摆角速度封顶基数（度/s） |
| `fortressTurnRadius(s)` | `max(0, def.turnRadius ?? 0)` | 最小转弯半径 R（格）；0 = 按底盘物理 |
| `fortressReverseFactor(s)` | `clamp(def.reverseFactor ?? 0.8, 0, 1)` | 倒退系数 rf |
| `brakeDecelMult(d)` | `i≤5 → 3−(i−1)/2`；`i>5 → 1−(i−5)×0.16`，`i = clamp(def.brakeInertia ?? 5, 1, 10)` | 刹停减速度倍率 |
| `terrainSpeedMod(x,y)` | 中心格地形 `moveModifier`（无地形 = 1，如水坑 0.5） | 地形只减速，不挡移动/弹道 |

输入谓词（由第 3 章操控层写入）：

- `throttle` = 有油门：`moveDir≠0 || reverse || 摇杆转向中 || desiredHeading≠null`
- `steering` = 摇杆转向中：`desiredHeading≠null && |wrapAngle(desiredHeading − heading)| > 3°`（3° 到位死区，防摇杆微抖）
- `coastTurn` = 滑行转向：`turnDir≠0 && !throttle`（仅 A/D 单独按下、无任何油门/朝向指令）
- `arcTurn` = 弧线转向中：`R>0 && (turnDir≠0 || steering) && !coastTurn`

### 2.1 速度模型

**目标速度向量** `(tx, ty)`（格/s）三选一：

| 情形 | 目标速度 |
| --- | --- |
| 弧线转向 `arcTurn` | `sgn·dir(heading)·arcW·R`，`sgn = reverse ? −1 : 1`（倒退 = 船尾先行倒弧）；v 与 ω 同比例 → 路径半径恒为 R、弧速不超上限 |
| 倒退 `reverse` | `−dir(heading) × maxSpd·rf·clamp(moveMag,0,1)·terrainMod`（沿船头反方向） |
| 平移输入 `moveDir≠0` | `moveDir/|moveDir| × maxSpd·clamp(moveMag,0,1)·terrainMod` |

履带底盘非弧线模式下叠加**转向阻力**：`turnDrag>0 && (turnDir≠0 || steering)` 时 `tx,ty ×= (1−turnDrag)`。

**加速度趋近**：每 tick 计算 `dv = |(tx,ty) − (vx,vy)|`，

- 刹停判定 `braking` = `dv>0 && v·Δv < 0`（松摇杆/换挡/倒退刹停均属减速）；
- 本 tick 最大速度变化量 `maxDv = accel × (braking ? brakeDecelMult(d) : 1) × (reverse ? rf : 1) × dt`（倒退时加/减速度同样 × 倒退系数）；
- `dv ≤ maxDv` 则一步到位至目标速度，否则沿 Δv 方向走 `maxDv`（惯性起步/滑停）。

**位移**：`(vx,vy)` 非零时按轴分离移动（`moveFortressAxis` 先 x 后 y）——撞墙贴墙滑动；中心跨格时 `pathVersion++` 触发全场敌人重寻路；位移后 `syncTurretMounts` 同步挂载炮塔。移动本身不改变朝向（平移），朝向只由转向段（2.2）改写。

### 2.2 转向三模式

每 tick 的航向增量 `dH` 按以下优先级取一种模式；`dH≠0` 时 `heading += dH`（回绕），挂载炮塔角随船体联动 `+= dH`。

#### 2.2.1 弧线转向（`turnRadius > 0`，两底盘通用覆盖）

转弯本身带动前行：堡垒绕外侧圆心走弧、本体随转。角速度（rad/s）：

```
arcW = min(fortressTurnSpeed(s)×DEG, maxSpd×terrainMod / R) × (reverse ? rf : 1)
```

即 ω 同时受转向速度封顶与「弧速不超速度上限、路径半径 ≥ R」约束。`turnRate = arcW/DEG`（度/s），再按 2.2.4 的输入分支施加。

#### 2.2.2 履带差速枢轴（`turnRadius = 0`、`chassis = 'tracked'`）

一侧履带正转、一侧反转的差速转向，**静止可原地转**（转速不乘速度比率）：

```
pivotCap = (2 × maxSpd / max(0.5, trackWidth ?? w)) / DEG   // 度/s
turnRate = min(fortressTurnSpeed(s), pivotCap) × (reverse ? rf : 1)
```

倒退时转速 × 倒退系数。滑行中转向速率恒定（履带动力转向，不随滑行衰减）。`turnDrag` 在此模式生效（见 2.1）。

#### 2.2.3 轮式自行车模型（`turnRadius = 0`、`chassis = 'wheeled'`）

运动学前轮转向模型，状态量 `steerAngle`（δ，rad）：

1. **前轮角积分**：`L = max(0.5, wheelbase ?? h×0.6)`；目标角——摇杆：`δ_t = clamp(steerDiff, ±steerMax)`（朝向差直接映射）；A/D：`δ_t = ±steerMax`（打满）；无输入：`δ_t = 0`（自动回正）。每 tick `δ += clamp(δ_t − δ, ±steerRate×dt)`（缺省 steerMax=35°、steerRate=120°/s）。
2. **附着钳制**：横向向心加速度不超 `gripMax`（缺省 8 m/s²，经 `m2c` 换算）——`tanδ_eff = clamp(tanδ, ±grip·L/max(vLon², 0.25))`，v<0.5 格/s 后不再收紧（高速打不死方向；运动学无漂移）。
3. **横摆角速度**：`ω = vLon × tanδ_eff / L`，再钳 `|ω| ≤ fortressTurnSpeed(s)×DEG`（turnSpeed 为可选封顶）；`dH = ω×dt`，`turnW = ω`。

其中 `vLon = v·dir(heading)`（纵向速度，倒退为负）。推论：**静止无转向能力**（v=0 → ω=0，方向盘语义）；**倒退时 ω 自然反向**（vLon<0，车尾语义无需额外翻转）；松油门滑行时转速随 vLon 衰减至停转。

#### 2.2.4 转向输入分支（弧线/履带模式共用）

| 分支 | 条件 | `dH` |
| --- | --- | --- |
| 摇杆追踪 | `steering` | `clamp(steerDiff, ±turnRate×DEG×dt)`——按转向速率追踪摇杆目标朝向，到位即停、不超调 |
| A/D 转向 | `turnDir≠0` | `sign(turnDir)×turnRate×DEG×dt×revFlip`（revFlip 见 2.3） |
| 松手过渡 | 无输入且 `desiredHeading==null` | `turnW` 指数衰减（见 3.3） |
| 摇杆已到位 | `desiredHeading≠null` 且在 3° 死区内 | `turnW = 0`（不计入过渡） |

### 2.3 倒车行为与车尾语义

- 倒退行驶沿船头反方向，极速与加/减速度均 × `reverseFactor`；弧线模式倒退 = 船尾先行的倒弧。
- **车尾语义**（履带/弧线的 A/D 分支）：倒退时 A 使车尾朝左（船头向右、heading+）、D 使车尾朝右（heading−），与摇杆倒车「船尾追踪摇杆」及真车倒车方向盘语义一致：
  `revFlip = (reverse || (coastTurn && vLon < 0)) ? −1 : 1`——翻转依据「实际纵向速度方向」而非仅倒退输入标志：松开后退键后堡垒仍在向后滑行时保持车尾语义，转向方向不突变，随减速平滑停转；有自由移动指令时以 `reverse` 标志为准（平移指令与船头轴向无关，不适用车尾语义）。
- 轮式底盘不需要 revFlip：倒退时 ω 由 vLon<0 自然反向（见 2.2.3）。

### 2.4 车身俯仰/侧倾悬挂（纯视觉）

汽车悬挂拟真：偏移 = **本 tick 实际加速度**（经加速度上限/地形/倒退系数约束后的真实 `Δv/Δt`，碰撞截断不计入）的反向映射。

- 投影：`aLon = a·dir(heading)`（纵向 → 俯仰），`aLat`（横向 → 侧倾）；死区按纵/横分量各自判定：`|aLon| < 0.05`、`|aLat| < 0.05` 各自视为零。
- 目标偏移（px）：`lt = (−ĥ·aLon + 侧向·aLat×0.4) × k`，`k = pitchGain×0.5`（缺省 4）；幅值钳 `|lt| ≤ leanCap`（缺省 4 px）。即：启动/加速 → 朝船尾后倾；减速/刹停 → 朝船头前倾；倒退天然镜像；弧线转向的向心加速度 → 向弯道外侧侧倾（×0.4）。
- **弹簧-阻尼二阶趋近**（悬挂手感）：`lean'' = ωn²(lt−lean) − 2ζωn·lean'`，`ωn = 2π×1.2 Hz`，`ζ = 0.5`（阶跃过冲约 16%，急加速冲过目标再回落；轻踩缓倾、地板油猛仰，起步不瞬间顶满）。软上限 `leanCap + 1` px（过冲余量，超限连同速度一起缩放）；目标归零且位移/速度双小则吸附清零。
- **巡航冻结**：匀速行驶（实际加速度进死区但未停稳）→ 保持当前倾角不归位、倾角速度清零；再次出现真实加速度时按新目标趋近。
- **停稳回弹**：停稳瞬间若带着保持的倾角（>0.3 px）→ 以此为初值做欠阻尼回摆 `lean(t) = L0·e^(−ζωt)·(cos ωd t + (ζω/ωd)·sin ωd t)`，`ζ=0.3`、`T=0.35 s`（反向过冲峰值 ≈ 0.37×L0），0.8 s 后强制归位；新加速度打断回弹。
- `pitchGain = 0`：关闭俯仰，取消回弹、倾角强制回正。
- 俯仰偏移随主体层：挂载炮塔、炮口火光、射线起点整体跟随偏移（引擎数值零改动，仅渲染）。

## 3. 操控输入

操控层（UI）把输入写入 `GameState` 的五个字段，引擎每 tick 消费：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `moveDir` | `{x, y}` | 期望移动方向（单位化前向量；0,0 = 无平移指令） |
| `moveMag` | 0~1 | 推进幅度：速度上限 = 最大速度 × moveMag（键盘恒 1，摇杆为模拟量） |
| `turnDir` | −1/0/+1 | A/D 显式转向：−1 左转、+1 右转、0 不转 |
| `desiredHeading` | number \| null | 摇杆目标朝向（rad）；引擎按转向速率追踪、到位即停 |
| `reverse` | boolean | 倒退模式：沿船头反方向行驶，极速/加速度 × 倒退系数，不改变朝向 |

### 3.1 键盘（坦克式键位）

| 键 | 现行语义 |
| --- | --- |
| `W` / `↑` | 油门：沿**当前船头正前方**行驶；按住期间前进方向每 tick 跟随船头刷新（`moveDir = dir(heading)`，摇杆受控时不刷新），`reverse = false` |
| `S` / `↓` | 倒退：沿船头正后方行驶（倒退系数生效），`moveDir = (0,0)`、`reverse = true` |
| `A` / `←` | 左转（`turnDir = −1`） |
| `D` / `→` | 右转（`turnDir = +1`） |
| W+S 同按 | 相互抵消 = 无油门（`moveDir=0`、`reverse=false`） |

- 键盘操控恒 `moveMag = 1`（全速），且每次键位变更都会清除摇杆朝向指令（`desiredHeading = null`，键盘优先）；松开摇杆时也回调键盘状态恢复键位方向/转向。
- 转向能力由底盘决定（见 2.2）：履带底盘静止按 A/D 可原地枢轴转；轮式底盘静止按 A/D 只会打动前轮角，无车速则无转向（方向盘语义）。无油门单独按 A/D（滑行转向）不做弧线驱动、不注入新速度，堡垒凭惯性滑行减速。
- 场景编辑模式或输入框聚焦期间，移动键不驱动堡垒。

### 3.2 虚拟摇杆（触屏/鼠标拖动通用）

按住拖动超过 4 px 视为摇杆操作（面板打开期间禁用）。核心状态：受控指针 id、档位 `mode`（`'fwd'|'rev'|null`）、直行迟滞 `straight`（迟滞方案用）、滤波状态 `fAngle/fDeriv/fTime`（滤波方案用）；松手即回未控态。

**死区与模拟量**：拖动长度 ≤8 px 为死区（保持已锁档位，只清空推进）；推出幅度映射推进量 `moveMag = min(1, len/40)`（满推 40 px = 全速）。

**偏角与扇区**：摇杆偏角 `stick = atan2(dx/len, −dy/len)`——0 = 正推（朝船头）= 前进，±180° = 正后 = 倒退；档内摇杆方向 = 堡垒运动方向。扇区边界 `SECTOR = 120°`：

| 档位 | 可达扇区 | 定档/钳制 |
| --- | --- | --- |
| 前进档 `fwd` | 偏角 ≤120°（前向 ±120°） | 首推 `|stick| ≤ 120°` 定 fwd；锁定期间拖入对侧扇区时吸在 ±120° 边界（不产生掉头指令） |
| 倒退档 `rev` | 偏角 ≥120°（正后方 ±60°） | 首推 `|stick| > 120°` 定 rev；同上钳在边界 |

**首推定档**：抓住摇杆时首次推出的扇区定档，锁定期间旋转摇杆不换档（前进档内倒推 = 掉头后船头领先开过去，不会倒车）；两扇区在 120° 处无缝衔接；要换向须松开摇杆解除受控后重新抓住定档。

**防抖**（编译期开关 `STICK_ANTI_JITTER` 双方案，均只作用于指令角、不劫持摇杆头视觉）：

- **平滑滤波（One Euro，现行，`STICK_ANTI_JITTER = 'filter'`）**：对扇区钳制后的偏角做 One Euro 滤波——`α = 1/(1+τ/dt)`、`τ = 1/(2πf)`、截止频率 `f = OE_MIN_CUTOFF(1.2 Hz) + OE_BETA(1.0) × |角速度|`（导数通道截止 `OE_D_CUTOFF = 1 Hz`）。**设定依据**：手抖是小幅低速角运动，被低截止频率强平滑；快速甩动角速度大，β 自适应抬升截止频率，延迟随动作速度自动降低——解决「滤波=迟钝」的经典矛盾，这是迟滞方案做不到的（迟滞只在直行位附近防抖，转向区内的抖动原样传导）。差分按环绕最短弧处理（倒档过 ±180° 边界时滤波不绕远路）；首次采样直接透传（避免从旧值摆入）。滤波后 `<1.5°` 微吸正（`FILTER_SNAP`）——EMA 只能逼近 0/π 不能到达，微吸正补足「回正=严格直行」语义。滤波状态随每次抓住摇杆重置。
- **迟滞死区（旧案，`'hysteresis'`，编译期保留可回退）**：直行↔转向双阈值——距直行位（fwd 档看正前 0°、rev 档看正后 180°）`<3°` 进直行（指令角吸为 0°/180°）、`>6°` 退出直行、3°~6° 保持原状态；迟滞带隔开进出阈值，手抖在边界往复不抽搐。抓取时 `straight` 初始为 true，松手随受控态复位。扇区钳制保证 fwd 档只可能吸正前、rev 档只可能吸正后。

**相对方向控制与 desiredHeading 追踪**：摇杆方向以堡垒**实时船头朝向**为基准（非抓住瞬间锚定）——正推 = 沿当前船头直行，斜推 θ = 移动并转向「当前船头 + θ」（转向中基准随船体一起转，保持一个偏角 = 持续转向，摇杆回正 = 立即沿当前船头直行，方向盘手感）：

```
world = heading + stick          // 目标朝向（相对船头叠加偏角）
fwd 档：moveDir = (sin world, −cos world)，desiredHeading = world，reverse = false
rev 档：moveDir = (0,0)，reverse = true，desiredHeading = world + π   // 船尾追踪摇杆方向
```

引擎侧：`steerDiff = wrapAngle(desiredHeading − heading)`，角差 >3° 为转向中，按转向速率追踪 `dH = clamp(steerDiff, ±turnRate×dt)`（到位即停、不超调；≤3° 视为到位，过滤摇杆微抖，且不计入松手过渡）。弧线模式（turnRadius>0）下该追踪走弧线转向。摇杆受控期间 `turnDir = 0`（A/D 不叠加）。

### 3.3 滑行与松手转向过渡

- **滑行转向**（`coastTurn`：仅 A/D 按下、无任何油门/朝向指令）：不注入新速度，堡垒凭惯性滑行减速；履带底盘枢轴转速恒定（动力转向），轮式底盘转速随纵向速度自然衰减至停转；弧线覆盖在滑行时不生效（`arcTurn` 要求油门）。
- **松手转向过渡**（常量 `TURN_COAST_TAU = 0.22` s）：转向输入解除（A/D 松开、摇杆松手/回死区）后角速度不瞬间归零——以输入解除前的 `turnW` 为种子按指数衰减：

```
turnW ← turnW × exp(−dt / TURN_COAST_TAU)
|turnW| < 0.2°/s 时归零
```

船头在过渡期间继续按衰减中的角速度惯性摆动。摇杆已到位（3° 死区内）时 `turnW` 直接清零，不进入过渡。
## 4. 炮位系统

炮位是堡垒上预定义的炮塔挂载点，定义于 `FortressDef.hardpoints`（`src/game/config.ts`），运行时挂载校验与坐标同步位于 `src/game/engine.ts`，槽位与视界弧渲染位于 `src/game/render.ts`。

### 4.1 Hardpoint 结构

```ts
interface Hardpoint {
  id: string; x: number; y: number
  size: MountSize                       // 'S' | 'M' | 'L'
  arc?: { start: number; end: number }  // 指定视角
  fixed?: number                        // 固定视角（度）
  types?: WeaponType[]                  // 类型限制
  hidden?: boolean; builtIn?: string    // 内置隐藏炮位
  zLevel?: number                       // 渲染层级
}
```

| 字段 | 语义 |
| --- | --- |
| `id` | 炮位唯一标识 |
| `x` / `y` | 堡垒局部坐标（格，锚点中心，可为小数）；运行时经 `fortressLocalToWorld()` 绕底座中心按 `heading` 旋转换算为世界坐标 |
| `size` | 炮位类型 S/M/L，与炮塔 `TurretDef.mount` 严格匹配才可挂载；炮塔侧占格由型号联动决定（`MOUNT_FOOT`：S=1×1 / M=1×2 / L=2×2） |
| `types` | 允许挂载的炮塔类型白名单（`WeaponType`：direct/lob/missile/beam/spray）；未配置 = 不限；配置为空数组视为不支持任何炮塔（校验拦截） |
| `arc` | 指定视角：起止角度（度，相对船头 0°=上方、顺时针为正），支持跨 0°（如 `{start:315,end:45}`）；未配置 = 全向 |
| `fixed` | 固定视角：炮口恒定朝向（度，-180~180，上方 0°，逆时针为负、顺时针为正），不追踪目标；与 `arc` 互斥，两者同存时 `fixed` 优先 |
| `hidden` / `builtIn` | 内置隐藏炮位：不出现在挂载 UI、不可挂卸，`builtIn` 记录预挂炮塔定义 id |
| `zLevel` | 渲染层级（缺省 1，越大越高），仅决定同尺寸炮塔在堡垒上的叠放顺序，须为数值 |

**视角三模式**：全视角（`arc`/`fixed` 均未配置，炮塔 360° 自由旋转）/ 指定视角（`arc` 起止角区间）/ 固定视角（`fixed` 恒定角）。引擎行为（`aim()` / `aimRestAngle()`）：

- 全视角：期望角 = 目标方位，无约束；
- 指定视角：目标方位须落在视界区间内才可开火（`hardpointArcContains`，跨 0° 正确判定），期望角经 `clampToHardpointArc()` 钳制到视界最近边界；无目标时炮口回中到视界中点（`hardpointArcMid`，跨 0° 区间取中正确）；
- 固定视角：期望角恒为固定角、炮口不追踪，是否开火由炮塔射角锥（aimCone）判定——目标进入固定朝向锥内即射。

角度归一化：`norm360()` 将任意角度回绕到 [0,360)，因此视界起止角允许大于 360° 或为负值，语义等价于回绕后的跨 0° 区间。`validateFortressDef()` 校验：`fixed` 须在 -180~180；`types` 不得为空数组；`zLevel` 须为有限数值；炮位坐标须在底座包围盒内。

**挂载初始朝向**（`mountTurret()`）：炮塔就位时 `angle = 堡垒朝向 + (fixed ?? 视界中点 ?? 0)`——全视角朝船头方向、指定视角朝视界中心、固定视角朝固定角；旋转速度为 0 的炮塔也能挂载即到位，与无目标回中角语义一致。

### 4.2 挂载与卸载规则

**校验**（`canMountTurret(s, defId, hardpointId)`，返回 `{ok, reason}`，按序检查）：

| 顺序 | 条件 | 拒绝原因 |
| --- | --- | --- |
| 1 | 炮塔定义存在 | 未知炮塔 |
| 2 | 炮位存在 | 炮位不存在 |
| 3 | 非内置隐藏炮位（`!hp.hidden`） | 内置炮位 |
| 4 | 尺寸匹配（`def.mount === hp.size`） | 需要 X 型炮位 |
| 5 | 类型兼容（`hp.types` 未配置或包含 `def.type`） | 炮位不兼容该炮塔类型 |
| 6 | 炮位未被占用 | 炮位已占用 |
| 7 | 金币足够（`s.gold >= def.cost`） | 废料不足 |

**挂载**（`mountTurret()`）：仅备战阶段（`phase === 'prep'`）可执行；校验通过则扣除炮塔造价，炮塔立即按炮位世界坐标就位（`x = 炮位世界坐标 − w/2`），初始朝向按 §4.1 规则确定，满耐久、等级 1；导弹类初始化挂架弹数 `rackLeft = max(1, burst ?? 1)`。

**卸载**（`unmountTurret()`）：仅备战阶段；返还半价（`floor(cost / 2)`）；`builtIn` 内置武器不可拆。通用拆除入口 `demolishAt()` 按坐标命中时炮塔优先于基地格处理，命中挂载炮塔即转 `unmountTurret()`。

### 4.3 炮塔随堡垒同步

- **位置同步**：`syncTurretMounts()` 每 tick 重算所有挂载炮塔的世界坐标（炮位局部坐标随 `heading` 旋转后的世界位置），索敌、弹道出生点、渲染均经炮塔中心读取，无需各自处理旋转。
- **朝向同步**：堡垒朝向每帧变化量 `dH`（含转向输入、松手惯性过渡等一切来源）同步累加到所有挂载炮塔的 `angle` 上（`t.angle = wrapAngle(t.angle + dH)`），随后调用 `syncTurretMounts()`。
- **瞄准基角**：挂载炮塔的瞄准基角 `aimBase()` = 堡垒 `heading`（地面炮塔恒 0 朝上），视界区间、固定角均相对船头解释，堡垒转向时射界整体随船旋转。

### 4.4 炮位与视界弧的渲染门控

渲染位于 `render.ts` 堡垒块，规则：

- `hidden` 内置炮位一律不绘制；
- **槽位圆圈与 S/M/L 字母**：仅在打开炮塔安装界面（卡片栏展开 `ui.turretPanel` 或处于挂炮模式 `ui.mountDefId`）时绘制；挂炮模式下与所选炮塔尺寸匹配、类型兼容且未被占用的炮位高亮（绿色加粗描边），已占用炮位绘制为暗色实心、不画字母；
- **视界弧**：仅两种情形显示——① 打开炮塔安装界面/挂炮模式时显示全部炮位的视界弧；② 选中某座炮塔时仅显示其挂载炮位的视界弧。弧以炮位为圆心、半径 1.1 格的扇形填充，角度相对船头 `start→end` 顺时针（画布换算 −90°），挂炮匹配的炮位用绿色调、其余用金色调；`fixed` 炮位不画扇形弧；
- **叠放顺序**：炮塔绘制按 `turretRenderKey()` 升序——主键为尺寸分级（S=0 < M=1 < L=2，小尺寸在底层），同尺寸按炮位 `zLevel`（缺省 1，地面炮塔视为 1），同键保持放置先后（稳定排序）；
- 诊断探针：每帧把槽位圈绘制数与视界弧绘制数写入 `window.__tdHp = { drawn, arcs }`，供自动化验证门控生效。

## 5. 内部空间与模块系统

内部空间是堡垒底座内的模块摆放区（背包式摆放，可旋转 90°）；模块无耐久、不可被敌人摧毁，仅可在备战期建造与拆除。定义位于 `config.ts`（`ModuleDef` / `MODULE_DEFS` / `ALLY_DEFS`），运行时位于 `engine.ts`（`canPlaceModule` / `buildModule` / `demolishModule` / `moduleBonuses` / `updateModulesAndAllies`）。

### 5.1 内部空间格阵

- `FortressDef.interior: { cols, rows }` 声明编辑网格尺寸；`interiorCells?: string[]` 为自由格阵（局部坐标 `"x,y"` 列表），缺省 = 左上角锚定的 cols×rows 满矩形。`fortressInteriorSet()` 输出全部可摆放格集合（按定义缓存）。
- 校验：内部空间逐格不得超出底座包围盒；配置自由形状（`shape`）时，内部格阵须逐格 ⊆ 形状格。
- 模块实例 `ModuleInst = { id, defId, x, y, rot, timer }`：`x/y` 为内部空间局部格坐标，`rot` 0/1 表示未旋转/旋转 90°，`timer` 为生产倒计时。

### 5.2 模块定义 ModuleDef


### 5.3 占格铺格与异型模块

- 编辑器铺格底格固定 5×5，模块占格按包围盒居中显示；点击格切换占位（彩色 = 占格，白色 = 空），至少保留 1 格。
- 包围盒 `w×h` 由铺格自动得出（派生只读，不可直接编辑）：每次切换后重算最小包围盒并把占格坐标归一化到包围盒原点；铺满整个包围盒时回到标准矩形态（不存 `shape`），挖掉格子即成 L/T 型等异型（存入 `shape`）。
- 异型占格允许不四连通（编辑器仅提示、不拦截）；`moduleBaseCells()` 读取 `shape` 时自动忽略越界格，`shape` 为空或全部越界时回退 w×h 满矩形。
- 旋转：`rot=1` 时绕 w×h 包围盒转 90°，映射 `(x,y) → (h−1−y, x)`（`moduleCells()`）；异型模块的贴图在局内按占格拉伸、随模块旋向。
- 模块 id 自动生成、不可编辑：新建为 `mod_<时间戳>` 格式经 `genId()` 生成，复制为 `<源id>_c<时间戳>`。

### 5.4 模块放置与拆除规则

**放置校验**（`canPlaceModule(s, defId, x, y, rot)`）：

1. 逐格界内：旋转后的每个占格单元都须落在内部空间格阵内（`x < 0 || y < 0` 或任一格不在 `fortressInteriorSet` → 「超出内部空间」）；
2. 逐格不重叠：与任一已放置模块的占格全集（`moduleInstCellSet`，异型模块的空洞格不占用）无交（→「与其他模块重叠」）；
3. 金币足够（→「废料不足」）。

**建造**（`buildModule()`）：仅备战期；扣造价，放入格阵；生产类模块初始化倒计时 `timer = interval ÷ 生产特殊格倍率`；建造后重算堡垒血量上限。

**拆除**（`demolishModule()`）：仅备战期；返还半价（`floor(cost / 2)`）；拆除后重算血量上限并把当前血量钳制到新上限内。

### 5.5 特殊格与加成倍率

- `FortressDef.interiorSpecials?: InteriorSpecial[]` 声明内部特殊格 `{ x, y, boost }`（局部格坐标）；`boost` 类别（`SpecialBoost`）：energy 电力 / ammo 弹药 / cooling 散热 / repair 维修 / range 火控 / produce 生产 / hp 结构 / speed 机动 / turn 转向，共 9 类。
- 倍率 `SPECIAL_MULT = 1.5`：模块的占格单元**逐格**覆盖了对应类别的特殊格（异型模块空洞不触发），该模块的对应属性 ×1.5（`moduleSpecialMult()`）；生产类模块对应为产出间隔 ÷1.5。同一模块覆盖多枚同类特殊格不重复叠加（一次命中即返回倍率）。
- 加成汇总（`moduleBonuses()`）：对全部已放置模块，逐属性累加 `字段值 × 对应特殊格倍率`，产出加成池：`energyRegen` / `energyCap` / `ammoRegen` / `ammoCap` / `coolingPool` / `repairPool` / `rangeBoostPool` / `hpBoostPool` / `speedBoostPool` / `turnBoostPool`。

### 5.6 模块对堡垒属性与资源的加成结算

| 属性 | 结算式（engine.ts） | 备注 |
| --- | --- | --- |
| 船体血量上限 | `def.hp + hpBoostPool`（`fortressMaxHp`） | 建/拆模块时重算 |
| 移动速度 | `max(0.2, def.speed + speedBoostPool)` 格/s | 下限 0.2 |
| 转向速度 | `max(10, def.turnSpeed + turnBoostPool)` 度/s | 下限 10 |
| 弹药上限/回复 | 上限 `AMMO.cap + ammoCap`；回复 `(AMMO.regen + ammoRegen)·dt` | 每 tick 结算并钳制到上限 |
| 电力上限/回复 | 上限 `ENERGY.cap + energyCap`；回复 `(ENERGY.regen + energyRegen)·dt` | 同上 |
| 堡垒散热 | `def.heatDissipation + coolingPool` 点/s | 全额直连、不按炮塔数摊薄，详见第 6 章 |
| 炮塔射程 | 每座炮塔增益 = `rangeBoostPool / 炮塔数`（无炮塔为 0） | 火控雷达增益池按炮塔数摊薄，作用于炮塔射程上限（炮塔域接口） |
| 炮塔维修 | 每座受损炮塔每 tick 恢复 `repairPool / 受损炮塔数 × dt` | 维修站功率均摊，受损越多越摊薄；备战/交战均生效 |

### 5.7 模块生产友军

生产类模块（`ModuleDef.produce = { kind, interval, cap }`）在 `updateModulesAndAllies()` 中逐模块倒计时推进（备战/交战都生效）：

- 倒计时归零时检查本模块产出的存活友军数（按 `producerId` 归属统计）：达到 `cap` 则不产出并把倒计时置 0.5s 稍后复查；未满则产出 1 个单位，倒计时重置为 `interval ÷ 生产特殊格倍率`。
- 出生点（`allySpawnPoint()`）：堡垒上方（迎敌侧）中点外侧 0.6 格，跟随堡垒移动；y 不低于出生带 `SPAWN_ROWS + 0.5`。
- 友军行为（`updateAlly()`）：全图索敌——取最近的**可攻击**（空/地适配匹配）存活敌人为目标，直线移动、无碰撞，进到射程边沿即停（射程单位米，按 25 m/格换算），按攻击间隔造成单次伤害；无敌人时原地待命；空中单位地面敌人无法攻击；阵亡时飘字提示并清理。

友军定义（`ALLY_DEFS`）：

| kind | 名称 | 血量 | 速度 格/s | 伤害 | 攻击间隔 s | 射程 m | 对空 | 对地 | 飞行 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| soldier | 士兵 | 120 | 1.2 | 8 | 0.8 | 12 | 是 | 是 | 否 |
| tank | 坦克 | 600 | 0.7 | 45 | 2 | 75 | 否 | 是 | 否 |
| plane | 战斗机 | 220 | 2.2 | 25 | 1 | 60 | 是 | 是 | 是 |

## 6. 热量管理

堡垒热量是全炮塔共享的过热资源：所有挂载/地面炮塔开火的产热汇聚到单一热量池，攒满即全炮塔停火。参数在 `FortressDef.heatCap` / `heatDissipation`，运行时位于 `engine.ts` 的 `addFortressHeat()` / `fortressCooling()` / `coolFortress()`。

### 6.1 热量池与过热状态

- `heatCap`：热量上限（校验范围 50~2000）；`heatDissipation`：自然散热速率（点/s，校验范围 1~100）。
- 堡垒运行状态：`s.fortress.heat` 为当前汇聚热量（钳制在 [0, heatCap]），`s.fortress.overheated` 为过热停火标志。
- **过热**：热量达到上限即 `overheated = true`，全部炮塔立即停火——不开火、进行中的连发被中断（连发计数与充能清零；冷却计时不清零）、持续型攻击终止。
- **恢复（迟滞）**：过热后热量须降到 `heatCap × OVERHEAT_RESUME`（`OVERHEAT_RESUME = 0.5`，即上限的 50%）才解除停火，迟滞区间防止在阈值附近抖动。

### 6.2 产热来源

- 炮塔每轮开火按其定义 `heatPerShot`（点/发，未配置 = 0）× 当轮发数调用 `addFortressHeat()` 汇入堡垒热量池；未配置产热的炮塔不产生热量。产热/停火判定、单发耗热属炮塔域，堡垒侧仅提供汇聚入口与停火门控。
- 热量百分比（占上限 0~100）同时作为炮塔资源门控标签可选用的资源键（`heat`），供炮塔侧按热量水位自控开火（炮塔域接口）。
- 模块影响：散热器模块的 `cooling` 叠加散热速率（见 §6.3）；散热类特殊格使覆盖其上的散热器功率 ×1.5（`SPECIAL_MULT`）。

### 6.3 散热结算

- 散热速率（`fortressCooling()`）= `heatDissipation + 散热器功率池 coolingPool`——散热器全额叠加到堡垒散热速率，不按炮塔数摊薄，多座散热器直接相加。
- `coolFortress(s, dt)` 每 tick 推进：`heat = max(0, heat − 散热速率 × dt)`，随后按 §6.1 的迟滞规则解除过热；自然散热与散热器在射击中、过热中均持续生效。
- 调用时机：交战阶段在全部炮塔 tick 之后统一散热（先汇聚产热、再散热）；备战阶段同样每 tick 调用——备战期炮塔不开火，散热表现为纯降温，保证开战时从低热量起步。

出厂堡垒（`FORTRESS_DEFS` standard「测试堡垒」）：`heatCap = 200`、`heatDissipation = 10` 点/s；散热器模块单座 `cooling = 8` 点/s（造价 110，占格 1×1，可叠加）。
## 7. 主体美术与表现

本章描述堡垒在战场上的主体视觉体系：贴图分层与几何回退、履带瓦片循环滚动、轮子美术组、地面落印、特效点粒子与车身俯仰/侧倾表现。以上均为**纯视觉层**，不参与碰撞与逻辑判定（碰撞体 = 形状格/包围盒）；代码依据为 `src/game/fortressFx.ts`、`render.ts`、`particles.ts`、`config.ts` 与 `engine.ts`（`fortressMarkColumns` / `trackPlacements` / 相位推进）。

### 7.1 堡垒贴图：分层与几何回退

**贴图配置**：`FortressDef.spriteBase`（底座贴图）与 `spriteBody`（主体贴图），取值为 dataURL 或 `/res` 路径（旧 `/sprites` 前缀自动兼容）。内置堡垒使用 `/res/fortresses/` 目录下的贴图（底座 `fort_1_02.png`、主体 `fort_1_01.png`，均为 160×256）；堡垒贴图不进素材库分类，直接以路径引用。履带/轮子素材则走素材库引用 id（内置履带瓦片 `builtin:library/track01` 位于 `/res/library/track01.png`，20×8，分类「底座」）。

**绘制规则**：两张贴图均**原比例居中显示、不缩放**——绘制尺寸 = 贴图自然像素 ×（cell / BASE_CELL），基准格统一 30px（zoom=1 时 1 贴图像素 = 1 画布像素，随用户缩放等比变化），中心对准底座包围盒中心。贴图仅视觉，不参与碰撞。

**外观层级**（堡垒绘制自下而上，整个上下文 = 包围盒中心平移 + `rotate(heading)`）：

1. **底座层**（始终渲染）：`spriteBase` 贴图 > 自由形状逐格（`shape` 格填堡垒色 + 描边，镂空处透明 = 真实碰撞体）> 几何回退（两侧履带侧裙矩形 + 中央底盘矩形）。
2. **履带层**：瓦片循环滚动（见 7.2）。
3. **轮子层**：与履带同层（见 7.3）。
4. **内部模块层**（仅建造/内部模式）或**主体层**（正常游玩）：主体层 = `spriteBody` 贴图（未加载回退为半透明甲板轮廓描边矩形）+ 金色船艏三角标记（指示朝向）+ 炮位标记。
5. 船体耐久条在堡垒上下文之外以屏幕空间绘制，不随船体旋转。

底座、履带、轮子三层**不随俯仰 lean 平移**；主体层随 lean 平移（悬挂拟真：履带贴地不动，车壳才倾，见 7.6）。贴图加载中/加载失败时自动落到几何回退。编辑模式下整个堡垒不绘制。

### 7.2 履带系统

**美术组配置**（`TrackDef`，`FortressDef.tracks[]`；未配置 = 无履带动画层）：

| 字段 | 含义 |
| --- | --- |
| `id` | 标识 |
| `x1, y1` | 前轮心（船头侧，局部格坐标） |
| `x2, y2` | 后轮心 |
| `radius` | 轮半径（格，0~2）= 头尾翻滚区长度 |
| `tile` | 瓦片素材（素材库引用 id / `/res` 路径 / dataURL） |
| `overlapPx` | 拼接重叠（贴图像素，0~30；缺省 2） |

- **只定义左侧履带**：右侧按堡垒中心线自动镜像（x → w − x），相位独立、差速对称。
- **原图直绘**：瓦片不旋转，图宽 = 履带宽度方向、图高 = 板长方向；尺寸一律取素材原图——绘制宽 = 图宽 ×（cell/30），板长 = 图高/30 格；**有效步长 =（图高 − overlapPx）/ 30 格**。
- 渲染关闭图像平滑（`imageSmoothingEnabled = false`）；瓦片贴图未加载时整条履带跳过。

**瓦片循环滚动**（`trackPlacements(t, phase, tileLen)`，纯函数可 sim）：

- 瓦片沿「前轮心→后轮心」直线段排布，相位 `phase`（格）对步长取模无缝循环；phase > 0 = 前进（瓦片向船尾流动），< 0 = 倒退反滚。
- **透视缩短翻滚**：两端轮半径区间为翻滚区，按**弧长参数化**——四分之一轮缘弧长 = R·π/2，瓦片沿履带路径等间距推进（θ = 弧长/R），位置 = R·sinθ 投影、长度 × cosθ、渐暗 alpha = 1 − 0.45·sinθ；`scaleY < 0.05` 的端点瓦片（翻到底面）不画。直线段全尺寸不透明。弧长参数化保证直线段与翻滚区交界处投影间距与瓦片压缩高天然匹配，重叠量全程保持、无缝隙。
- **相位 = 位移同步**：引擎每 tick 累加 `dphase = (vLon − turnW × sx) × dt`（vLon = 纵向速度分量，格/s，倒退为负；turnW = 当前转向角速度 rad/s；sx = 该列横向偏移，格，右舷为正）。转向差速自然成立（右转 → 右侧内侧变慢、左侧外侧变快），原地转向两侧一正一反，倒退反滚。
- **渲染帧插值**：`trackPhase[]` 在前后两个逻辑态之间按插值系数逐元素 lerp（与堡垒位置/朝向同一套逻辑帧→rAF 插值机制），消除「逻辑帧低频 + 步长整倍数滚动」导致的满速频闪混叠（履带看似静止）；前一状态缺少对应相位元素时直接取当前值。仅视觉平滑，相位物理同步不变。

### 7.3 轮子美术组

**配置**（`WheelDef`，`FortressDef.wheels[]`；与 `tracks` 独立共存——半履带布局 = 前轮 `wheels` + 后履带 `tracks` 同配即得）：

| 字段 | 含义 |
| --- | --- |
| `id` | 标识 |
| `x, y` | 轮心（堡垒局部格，原点左上，−y = 船头方向） |
| `r` | 轮半径（格，0~3） |
| `sprite?` | 轮子贴图（素材库引用 id / `/res` 路径 / dataURL；缺省 = 几何轮胎） |
| `steered?` | 转向轮：随前轮转角 δ 偏转（前轮 = true；缺省 false） |

**渲染**：与履带同层级（底座之上/主体之下）、随船体旋转、不随俯仰 lean。贴图按原比例以高度 2r 等比缩放绘制；缺省回退为几何轮胎——深色圆角矩形（纵向，−y = 船头）+ 轮毂线（标示偏转方向）。配置了贴图但尚未加载时该轮跳过（与履带瓦片同口径）。`steered` 轮绘制时旋转 `s.fortress.steerAngle`（轮式底盘前轮转角；履带底盘该值恒 0）。

### 7.4 落印系统

履带印/轮印按各侧**真实位移**在地面落印：位移源直接复用引擎 `fortress.trackPhase[]`（与船体履带瓦片滚动同一数据源），弧线内外弧差速、倒退反滚天然正确，印与轮永不脱节。

**统一相位列**（`fortressMarkColumns(fd)`）：

- 每条履带产生**两列**（定义列 + `mirror=true` 的右侧镜像列）在前，**每个轮子一个退化单列**（段长 0，x1=x2=轮心）在后；列数 = tracks×2 + wheels，`trackPhase` 数组同布局、长度自适应（列数变化时锚定当前相位，不产生落印爆发）。
- 轮子列未配贴图时沿用内置履带瓦片 `builtin:library/track01`（overlapPx = 2）。
- 各列相位推进统一公式：`dphase = (vLon − turnW × sx) × dt`。

**落印规则**（`updateTrackMarks`，纯函数可 sim；渲染端持 `marks`/`TrackMarkState` 按 rAF 驱动）：

- **印距**：`trackMarkStep = max(0.2, (图高px − overlapPx) / 30)` 格——与履带瓦片滚动同口径，印迹连续无缝、与履带板一一对应。瓦片贴图未加载的列跳过。
- **步进落印**：每列维护带符号余量 `acc += 相位差`；`|acc| ≥ 印距` 则在当前接地点连落至不足一个印距——倒退先抵扣正向余量再落反向印，不错印不漏印。
- **启动印**：静止→移动瞬间（该列相位由不变变为变化）立即落一印——履带本就压着地面；换向经过静止帧也会重落一印。后续间距仍按余量步进，不密不疏。
- **接地点 = 运动方向后端**：世界速度换算到船体局部（局部 −y = 前进方向），履带段方向与局部速度点积 > 0.05 格/s 取 (x1,y1) 端、< −0.05 取 (x2,y2) 端、≈0 取段中点（轮子段长 0 恒取轮心）。前进时印紧贴船尾缘落地即露出，倒退时自然取前端；弧线/差速时各列独立按各自接地点落印。镜像列 x 按 `fd.w` 镜像。落点经堡垒中心 + heading 旋转到世界坐标，印角度 = 落地时 heading。

**视觉与生命周期**：

- 印 = 瓦片贴图经 `tintedFx` 压暗（`#2E2A24`）的压印版，基础透明度 `TRACK_MARK_ALPHA = 0.25`，随 zoom 缩放。
- 寿命 `TRACK_MARK_LIFE = 12` 秒（**游戏时间**，暂停不老化）：前 2 秒全亮，末 `TRACK_MARK_FADE = 10` 秒线性渐隐到 0。
- 容量 `TRACK_MARK_CAP = 600`，超出 FIFO 丢最旧。
- **地面层**：地形之上、地面粒子与堡垒底座之下；编辑模式不产生不绘制；游戏时间回退（重开/读档）自动清空全部印。

### 7.5 特效点系统

**配置**（`FortressEffectPoint`，`FortressDef.effects[]`；贴附船体的程序化粒子发射点，仅视觉，不参与碰撞）：

| 字段 | 含义 |
| --- | --- |
| `id` | 标识（不可重复） |
| `x, y` | 发射点堡垒局部坐标（格，可为小数；须在包围盒内，允许落在形状格外的镂空/边缘） |
| `kind` | 种类：`smoke` 烟雾 / `flame` 火焰 / `dust` 尘土 / `spark` 火花 |
| `state` | 播放状态门控：`idle` 停止时 / `move` 移动时 / `both` 始终 |
| `layer?` | 渲染层级：`ground` 地面层 / `air` 空中层（缺省 dust=ground，其余=air） |
| `rate?` | 发射速率 粒/s（>0~120，缺省按 kind） |
| `size?` | 粒子尺寸 格（>0~2，缺省按 kind） |
| `life?` | 粒子寿命 秒（>0~10，缺省按 kind） |
| `inherit?` | 堡垒速度继承比例 0~1（缺省 dust=0.3，其余=0） |

**kind 缺省口径**（`KIND_DEFAULTS`，`effectParams` 逐字段回退）：

| kind | layer | rate | size | life | inherit |
| --- | --- | --- | --- | --- | --- |
| smoke | air | 8 | 0.12 | 1.3 | 0 |
| flame | air | 24 | 0.08 | 0.28 | 0 |
| dust | ground | 14 | 0.1 | 0.9 | 0.3 |
| spark | air | 7 | 0.05 | 0.22 | 0 |

**发射机制**（`emitFortressEffects`，纯函数可 sim；渲染端持「特效点 id → 发射累加器」按 rAF 驱动，编辑模式不发射）：

- 发射器贴附船体：`effectWorldPos` 将局部坐标经堡垒中心 + heading 旋转到世界坐标（与堡垒渲染上下文同一变换）；**粒子离口即在世界空间独立运动**——堡垒开走后烟留在原地上升扩散。
- 状态门控：堡垒速度模 > 0.05 格/s 判定为移动；`idle` 点移动时停发、`move` 点停止时停发。
- 按 rate 累加器跨帧连续发射（避免小数粒截断闪烁）；各点累加器初值按坐标 hash 错开首粒相位；发射口 ±0.04 格微抖动。
- 粒子初速按 `inherit` 比例叠加堡垒速度（尘土被车带起前扬；烟囱烟垂直上升不随车）。

**粒子行为**（按 kind 分化，视觉与全局粒子口径统一）：

- **smoke**：灰色（`#78766E`）上升扩散烟团，初速向上 0.3~0.5 格/s + 横向微抖，drag 1.2，grow 1.8（膨胀）+ growUntil 0.5（年龄过半后冻结尺寸、仅 alpha 随寿命渐隐），fadeIn 0.12s；寿命 ±15% 抖动（×(0.85+rand×0.3)）。
- **flame**：短寿命加法火焰，金（`#F0C85A`）→ 橙（`#D87828`）寿命内渐变 + flicker 0.4 高频闪烁，初速向上 0.45~0.75 格/s，drag 1.5，grow −1.2（收缩）。
- **dust**：地面扬尘，褐色（`#96825F`），随机侧向 0.2~0.6 格/s 弥散 + 继承车速前扬，drag 1.6，grow 1.6 + growUntil 0.4，fadeIn 0.1s。
- **spark**：随机方向短促亮线（1.5~4 格/s），淡金（`#F0DC78`），drag 6，`streak` 电焊式拖尾（绘制时沿速度反向拉 0.05s 亮线）。

**粒子双通道**：

- `ground` 池 = **地面层**：地形之上、堡垒底座之下（绘制在履带印之后），尘土等；
- `air` 池 = **空中层**：渲染末尾最上方，烟雾/火焰/火花。
- 两通道共用 `drawParticlePool` 与 `stepParticles`（渲染端 wall-clock dt，clamp 0.1s 防后台大步长）；每池容量 `PARTICLE_CAP = 400`，超出回收最老粒子。
- 粒子绘制为贴图化软粒子：烟尘（grow > 0）走 `smoke32` 贴图且不加光（source-over），其余走 `particlealpha32` 加法发光（lighter）；颜色渐变 color→colorEnd 按寿命 lerp 并量化 8 档做着色缓存；贴图未加载/无 DOM 回退 arc 圆点；离屏粒子跳过。
- 粒子逐帧运动 = 位置积分 + drag 减速 + 尺寸 grow 积分（growUntil 截止后冻结）+ 可选湍流正交噪声漂移 + 寿命到期回收。

### 7.6 俯仰/侧倾的渲染表现

车身俯仰为汽车悬挂拟真的**纯视觉位移**（`fortress.leanX/leanY`，屏幕像素），不参与任何逻辑。

**目标倾角**：按本 tick 实际生效加速度（经加速度上限/地形/倒退系数约束后的真实 Δv/Δt，碰撞截断不计入）反向映射——纵向加速度 → 俯仰（加速后倾/减速前倾，倒车时语义随真车反向），横向（向心）加速度 × 0.4 → 侧倾（弯道外侧压倾）。强度 `pitchGain` 0~10（缺省 4，0 = 关闭并强制回正），映射系数 = pitchGain × 0.5 px/(格/s²)；死区 0.05 格/s²；目标幅值钳制 ±`leanCap` px（1~8，缺省 4）。

**动态模型**：弹簧-阻尼二阶趋近（ωn = 2π×1.2Hz，ζ = 0.5，约 16% 阶跃过冲——轻踩缓倾、猛加速冲过目标再回落），软上限 = leanCap + 1px 过冲余量。匀速巡航（实际加速度进死区）时倾角**冻结保持**不归位；停稳瞬间若带倾角（> 0.3px）则以当前倾角为初值做欠阻尼回摆（ζ = 0.3、周期 0.35s，反向过冲约 0.37 倍、0.8s 衰减归位）。

**渲染表现**：

- **主体层**整体按 lean 平移——leanX/leanY 为世界系位移，绘制时按 heading 逆旋转换算到船体系后 translate；
- **挂载炮塔**连同其炮口火光、射线/喷射起点同帧随 lean 平移（与主体精灵层一致）；地面炮塔与编辑模式不受影响；
- **底座、履带、轮子不动**——履带/轮贴地、只有车壳倾，与落印接地点的物理语义一致。
## 8. 堡垒编辑器 UI

堡垒编辑器是堡垒类型（FortressDef）的编辑器：编辑「这型堡垒长什么样」，而不是当前对局的堡垒状态。入口为 DEBUG 面板（DebugPanel）的「堡垒」页签；面板为全屏覆盖层，打开期间主界面的备战倒计时暂停（交战照常进行）。

### 8.1 整体布局

页签内为左右两区：

- **最左：堡垒类型库竖列**（96px）。顶部整宽「新建」按钮，其下显示当前出战堡垒名；堡垒条目纵向列表，选中项高亮并带左侧红条。每条目显示名称（出战堡垒带 ★）与来源徽标：`内置` / `内置·已改`（被覆盖编辑的内置）/ `自定义`。
- **右侧：内容区**，自上而下为：操作行 → 基础属性 + 贴图板块（宽屏左右并置，窄屏纵向堆叠）→ 编辑区（预览画布 + 参数区，宽屏画布居左参数居右）→ 校验结果面板。

操作行包含：撤销 / 重做、复制为新自定义、保存、放弃改动（有草稿时）、删除 / 恢复出厂（非出厂内置时）、设为出战（下局生效）/ 设为出战并重开（非出战堡垒时），以及行内消息提示。

### 8.2 编辑流程：草稿—保存模型

堡垒编辑采用显式保存模型，与炮塔/弹丸/模块页签的「即改即落盘」不同：

1. 左侧列表**选择堡垒**（内置/自定义均可直接编辑），或点「新建」（基于测试堡垒深拷贝，形状展开为显式满矩形自由网格，id 为 `fort-<时间戳>`，命名为「自定义堡垒N」），或「复制为新自定义」（拷贝当前条目的包围盒/形状/内部空间/特殊格/特效点/热量/炮位/颜色，机动参数仅拷贝耐久/速度/转向速度/加速度四项（turnRadius、倒退系数、刹停惯性、俯仰参数、底盘及底盘参数组不拷贝、保留模板默认），另存为新 id）。
2. 首次改动时以当前定义为基线深拷贝出**编辑中副本（draft）**；此后一切修改都经统一的 `mutate` 入口作用于草稿。编辑器预览画布与参数区始终渲染 `draft ?? 库中定义`，因此**未保存的改动即时反映在编辑器预览中，但不影响类型库与主界面**。
3. **保存**：先经 `validateFortressDef` 校验，通过才 upsert 进堡垒类型库并落盘；不通过则保存按钮显示红色徽标「保存（N 项待修复）」，点击后在操作行内联显示首条错误与总数。保存后草稿与撤销历史清空。
4. **放弃改动**：丢弃草稿回到库中定义。切换堡垒、新建、复制、删除均隐式放弃草稿并清空撤销历史。

数字输入框（FortNumInput）为 `type=text + inputMode=decimal`：聚焦期间展示本地编辑文本（允许 `-`、`1.` 等中间态），可解析为数值时实时提交，失焦回落到外部值，保证负数与小数可正常输入。

### 8.3 基础属性与字段显隐规则

基础属性板块内置也可直接修改，字段包括：名称、耐久、移动速度、加速度、刹停惯性、车身俯仰、俯仰位移、倒退系数、转向速度、转向半径、底盘类型、热量上限、自然散热、颜色。包围盒 `w×h` 由形状派生为只读展示，并同步显示内部格计数。

**按底盘类型分组的底盘参数区**：底盘下拉（履带/轮式）决定其下参数组的显隐——

- 履带（tracked，缺省）：履带间距、转向阻力；
- 轮式（wheeled）：轴距、前轮转角、方向盘转速、横向附着上限。

转向半径为两底盘通用字段：0 = 按底盘物理（履带差速可原地枢轴转向；轮式前轮转向，静止不能转向），>0 = 覆盖为两底盘通用的绕外侧圆心弧线模式。

字段显隐的总体约定与炮塔参数面板一致：字段可携带显隐谓词（`showIf`，按当前定义状态判定），无谓词字段按「该字段已配置」判定显示；可清空字段删空即回到「未配置」（使用缺省值）。堡垒页签内的条件显隐均按此原则以条件渲染实现，例如：炮位「隐藏内置」勾选后才出现内置武器下拉；视角选「指定视角」才显示起°/止°、选「固定视角」才显示角°；轮式底盘才显示轮子物理参数等。

### 8.4 预览画布：外部模式 / 内部模式

编辑区左侧为 SVG 预览画布，顶部「预览」按钮切换**外部模式**（底盘·炮位·特效点）与**内部模式**（内部格阵·特殊格），切换时子工具分别复位为「铺/擦底盘格」/「铺/擦内部格」。

画布几何：背景格列数取 `clamp(w+2, 9, 30)`、行数取 `clamp(h+2, 10, 18)`，格像素取 `clamp(360/列数, 16, 30)`；堡垒按整数格偏移居中渲染，点击反向换算为堡垒局部坐标，局部坐标为负的画布留白区不可交互。画布图例行随模式切换说明各色块含义。

**外部模式**子工具：铺/擦底盘格、炮位落点、特效点。渲染内容自下而上：底盘格（堡垒色，内部空间格深色覆盖）→ 底座贴图 → 履带瓦片与轮圆标定线 → 轮子 → 主体贴图 → 选中炮位视界（绿扇/绿圈/单射线）→ 中心原点红色十字标记 → 炮位圆点 → 特效点彩点。底座/主体贴图按原始像素尺寸 1:1 绘制、中心对准包围盒中心（与游戏内渲染一致），不拦截格子编辑；贴图尺寸经 onload 缓存，未就绪的帧跳过。

**内部模式**子工具：铺/擦内部格、特殊格。底座贴图作为垫底参照绘制在格子层之下（主体不显示），有底图时内部格/底盘格填充调半透明透出底图；内部模块格深色、底盘非内部格浅色、特殊格黄底并标注加成名首字。

### 8.5 底盘格与内部空间编辑

- **铺/擦底盘格**：点击切换形状格（shape）。每次改动后 `w/h` 重算为形状包围盒。**级联擦除**：擦掉底盘格时，该格对应的内部格与其上的特殊格一并移除（内部格为隐式满矩形时先实化再剔除），避免「内部空间越出形状」。
- **铺/擦内部格**：点击切换 `interiorCells`，目标格必须落在底盘格内（否则不响应）；擦掉内部格连带清除其上特殊格；「重置为矩形」按钮清空 `interiorCells` 回到缺省矩形。缺省矩形由 `interior.cols × rows` 定义（左上角锚定），在内部模式参数区可改（≥1 整数，清空自由格阵后生效）。
- **特殊格**：下拉选择加成类型（能量/弹药/散热/维修/射程/生产/血量/速度/转向，各 ×1.5，生产类为间隔 ÷1.5）或「清除特殊格」，点击内部格写入 `{x, y, boost}`；选「清除」时点击即移除该格特殊标记。模块占格覆盖特殊格时对应属性加成生效。

模块实例的摆放不在编辑器内进行——那是局内备战期的建造行为（内部建造模式：隐藏主体只露底座，点模块卡片后点底座格放置，幽灵提示合法性，R 旋转，可拆除返还）。模块类型本身的编辑在「模块」页签：5×5 铺格画布点击切换占格（彩色=占格、白色=空，至少保留 1 格），包围盒 `w×h` 由铺格自动得出（全满包围盒回标准矩形、不存 shape），挖格即成 L/T 等异型并给出四连通提示；模块贴图锚定素材库「模块」分类条目，缺省为色块+名称。

### 8.6 履带编辑组

外部模式参数区的履带板块管理 `tracks` 数组（瓦片循环滚动动画，仅视觉；未配置 = 无履带动画层）：

- **增删**：「添加」生成默认履带（前/后轮心置于左侧中轴线首尾，半径 0.5 格，瓦片取内置库履带瓦片，重叠 2px）；每条末尾 × 删除，删空后移除 tracks 字段。
- **标定参数**：前轮心 x/y、后轮心 x/y（堡垒局部格，0.1 步进）、轮半径（格，= 头尾翻滚区长度）、重叠 px（贴图像素，有效步长 = 图高 − 重叠）。
- **贴图上传**：上传 PNG/JPEG 入素材库「底座」分类并以条目 id 引用；瓦片尺寸取原图。
- **预览**：画布按当前标定静态（相位 0）渲染履带瓦片——只标定左侧，右侧自动镜像；瓦片带逐片透明度/纵向缩放，前后轮心处画红色细线轮圆作为标定参考。
- **校验**：轮心坐标须为数值且前后轮不重合，半径 0~2 格，重叠 0~30px，必须配置瓦片素材。

### 8.7 轮子编辑组

轮子板块管理 `wheels` 数组（轮式底盘美术与落印单元；与履带独立共存——半履带 = 前轮子 + 后履带）：

- **增删**：「添加」时前两个默认置为转向轮（y=1，船头侧），其后添加的默认在车尾侧（y=h−1），半径 0.4 格；× 删除，删空后移除 wheels 字段。
- **参数**：轮心 x/y（0.1 步进）、半径（0.05 步进，校验 0~3 格）、「转向」勾选（转向轮随前轮转角 δ 偏转，前轮勾上、后轮不勾）。
- **贴图上传**：入素材库「底座」分类并引用；未配贴图 = 几何轮胎（深色圆角矩形）。落印 = 轮心压痕，沿用履带瓦片。
- **预览**：δ=0 静态渲染，贴图按原比例以 2×半径定高；转向轮画红色轮毂参考线，非转向轮为灰色。

### 8.8 炮位编辑

外部模式参数区的炮位板块管理 `hardpoints`（尺寸 + 类型限制 + 视角 + 层级）：

- **添加/删除**：「添加」在包围盒中心格生成 S 型炮位并自动选中；每条「删」移除。
- **摆放**：点炮位 id 按钮选中该炮位并切到「炮位落点」工具，随后点击画布把锚点设到格中心（`cx+0.5, cy+0.5`）。
- **坐标**：以 dx/dy 输入框直接编辑，原点 = 堡垒中心（画布上有红色十字「原点」标记），dx 向右为正、dy 向上为正，单位格、步进 0.1，输入值钳制在 ±w/2、±h/2 内。
- **尺寸**：S/M/L 下拉；画布上圆点大小随尺寸区分，隐藏内置炮位显示为灰色，选中炮位红色描边。
- **视角三模式**：全视角（360° 自由旋转，arc/fixed 均不配置）/ 指定视角（起°~止°区间，支持跨 0°）/ 固定视角（炮口恒定朝向，−180~180°，上方 0°、逆负顺正）。选中炮位的视界在画布实时绘制：区间视角画绿色扇形、全向画绿色虚线圆、固定视角画单射线；半径取画布对角线，超出部分自动裁切。
- **类型限制**：全部炮塔类型以复选框列出，默认全勾（勾 = 可装该类型；全勾时清除 types 字段 = 不限）；全不勾 = 不支持任何炮塔，行内红字提醒且保存校验报错。尺寸限制先于类型限制生效。
- **隐藏内置**：勾选后炮位不出现在局内挂载 UI，并出现内置武器下拉（仅列出 mount 尺寸等于该炮位的炮塔定义）；取消勾选同时清除内置武器绑定。
- **层级**：zLevel 整数，缺省 1（填 1 即清回未配置）。

### 8.9 特效点编辑

「特效点」工具下点击画布空格添加特效点（新点固定默认为 烟雾 + 始终），点击同格移除。参数区列表逐项配置：类型（烟雾/火焰/尘土/火花）、播放时机（停止时/移动时/始终，引擎按堡垒当前速度切换）、渲染层级（地面 = 堡垒底座之下 / 空中 = 最上；缺省尘土为地面、其余为空中）、x/y 坐标（0.1 步进）、删除。画布上以类型对应颜色的彩点显示并标注类型与时机。特效为程序化粒子，仅视觉。

### 8.10 撤销 / 重做

- 历史栈容量 50 步，记录草稿快照。所有编辑经统一 `mutate` 入口压栈：首次编辑以**编辑前状态**为基线入栈，此后每次编辑压入新快照；800ms 时间窗内的连续编辑（名称打字、步进器连击）合并为一步（替换栈顶）。
- 撤销后再编辑会截断重做分支。
- 操作行「撤销」「重做」按钮按栈位禁用；快捷键 Ctrl+Z 撤销、Ctrl+Y / Ctrl+Shift+Z 重做；焦点在输入框/下拉框内时放行，交给原生文本撤销。
- 切换堡垒、保存、新建、复制、删除/恢复出厂时清空历史。历史仅存于内存，仅覆盖草稿期编辑，不涉及已落库数据。

### 8.11 校验与主界面同步约定

保存闸 `validateFortressDef` 的规则：数值区间（耐久 500~20000、移动速度 0.2~6 格/s、转向速度 15~240°/s、转向半径 0~20 格、加速度 0.5~20 格/s²、热量上限 50~2000、自然散热 1~100 点/s、刹停惯性 1~10、车身俯仰 0~10、俯仰位移 1~8px、倒退系数 0~1，及履带/轮子/底盘分组参数各自区间）；形状格坐标合法、无重复、4-连通成整体（允许镂空）、w/h 等于形状包围盒；内部空间 ⊆ 形状格；炮位锚点在包围盒内；特效点在界内；炮位类型限制不得全不勾；固定视角 −180~180°。草稿存在时底部校验面板常绿/红提示（「校验通过：网格连通、内部空间/炮位/特效点/特殊格均在界内」或逐条列出待修复项）。

与主界面的效果同步：

- **编辑器预览**始终渲染草稿，未保存即可看到效果。
- **保存**后定义就地并入 FORTRESS_DEFS 注册表；渲染层按 `fortressDef(s)` 逐帧查表，因此外观类改动（贴图/履带/轮子/形状/炮位/特效点）在当前对局画面中即时可见。
- **对局数值**（耐久、机动、热量等）在开局（initialState）时快照进游戏状态，出战堡垒的此类改动**重开一局后生效**；保存消息对此有明确提示。
- **设为出战**：写入出战选择，下一局生效；**设为出战并重开**经 onRestart 回调让主界面立即以 `initialState()` 重建本局并清理选择/模式状态。存在未保存草稿时禁止设为出战。

## 9. 堡垒类型库、口令与持久化

### 9.1 堡垒类型库

运行期的堡垒类型注册表 `FORTRESS_DEFS` 由两部分合成：**内置堡垒**（编译期常量，出厂定义，含默认出战堡垒「测试堡垒」）与**自定义堡垒**（持久化的 `customs` 列表）。模块初始化时留存内置出厂快照，随后读入本地堡垒库并把自定义条目并入注册表：同 id 原位替换（对内置 id 即构成**覆盖编辑**），新 id 追加；引擎按 id 查表，无需感知来源。

覆盖编辑语义：

- 内置堡垒可直接编辑；保存时整条定义作为自定义条目 upsert 进 `customs` 并覆盖注册表中的同名内置。被覆盖的内置在列表中显示「内置·已改」，操作行提供「恢复出厂」。
- 删除条目分两种：纯自定义 = 从库与注册表移除；内置覆盖 = 从 `customs` 移除并把注册表该 id 恢复为出厂快照（深拷贝）。若被删条目是出战堡垒且删除后该 id 已不存在，出战选择回落到默认堡垒。
- `isBuiltinFortressOverridden(id)` 判定「出厂内置 + 存在同 id 自定义条目」，编辑器据此切换「删除」/「恢复出厂」按钮语义。

**选择当前堡垒（出战选择）**：`selectedId` 与 `customs` 一并持久化。`setSelectedFortressId` 只接受注册表中存在的 id（不存在则保持默认）。开局 `initialState()` 按 `selectedId` 取定义（找不到回退默认堡垒），并把 id 记入 `GameState.fortressDefId`；运行期 `fortressDef(s)` 按此 id 在注册表查表。

### 9.2 持久化模式

localStorage 键与内容：

| 键 | 内容 | 写入时机 |
| --- | --- | --- |
| `td-fortress-lib-v1` | `{version, customs, selectedId}` 堡垒类型库 | 堡垒保存/删除/恢复出厂、设为出战、口令导入 |
| `td-turret-defs` | `{version, data}` 炮塔定义全量 JSON | 炮塔编辑 bump（saveAll）等 |
| `td-projectile-arts` | 弹丸美术库全量 JSON | 同上 |
| `td-module-defs` | 模块库全量 JSON | 模块编辑 bump、口令导入 |
| `td-level-config-v7` | 关卡配置（level.ts 通道） | 战场编辑器「应用并重开」、口令导入 |

共同模式：

- **模块初始化即加载**（import persist 即完成）：读出后**就地 splice 替换注册表内容**，保持各处 import 引用有效，引擎/渲染零改动；无存储环境或解析失败一律静默用出厂默认。
- **信封与版本**：炮塔/弹丸/模块三通道信封格式为 `{version, data}`，version 不符丢弃用默认；旧语义的 fireRate（轮/s）数据加载时取倒数迁移并回写。炮塔数据加载后统一经 `applyMountFoot` 归一化占格。堡垒库信封 version 不符则整体弃用默认。
- **bump 约定**：炮塔/弹丸/模块等页签的每次编辑经 bump 立即 saveAll 落盘；堡垒页签例外——走草稿—保存模型，由保存/删除/出战等动作各自落盘（见 §8.2）。
- **出厂快照与重置**：初始化时留存炮塔/弹丸/模块/内置堡垒四份出厂深拷贝。`resetPersistedToDefaults` 把炮塔/弹丸/模块三注册表清回出厂并移除对应三个键（**不动堡垒类型库**）；`resetModuleDefsToFactory` 仅模块库回出厂；堡垒的出厂还原走逐条目「恢复出厂」（§9.1）。
- **写入失败显式化**：堡垒库写盘失败（无存储环境、配额满等）时置 `fortressLibPersistFailed` 标志——改动仍更新内存注册表，编辑器保存后提示「本地存储写入失败（空间不足），刷新后将丢失」；下一次成功写盘清除该标志。

### 9.3 口令携带（导入导出）

配置口令 = `base64(JSON(bundle))`，UTF-8 安全的纯 JS base64（无 btoa/Buffer 依赖），解码容忍粘贴带入的空白/换行。bundle 结构：

```ts
{
  app: 'td-config',
  version: 4,
  turretDefs,      // 炮塔定义全量
  projectileArts,  // 弹丸美术库全量
  level,           // 关卡配置
  assets,          // 素材库用户上传条目（内置素材不导出）
  fortressLib,     // 堡垒类型库 {version, customs, selectedId}
  moduleDefs,      // 模块库全量
}
```

- **导出**：DEBUG 面板「导出」按钮实时取注册表现状打包，弹窗展示口令串并支持一键复制；另有美化 JSON 导出（本地 `td-config.json`，便于直接编辑）。
- **导入**：弹窗粘贴口令后，先完整解析 + 形状校验（app 标识、格式版本 ∈ 1/2/3/4、turretDefs/projectileArts 为数组、fortressLib.customs 为数组、moduleDefs 为数组、level 各字段齐全），**全部通过后才一次性就地替换注册表并落盘**；任一步失败整体拒绝、不写坏现有数据。JSON 文本（以 `{` 开头）与 base64 口令双兼容。导入成功后页面自动重载，全部状态从 localStorage 重建。
- **格式版本兼容**：bundle 的 assets、fortressLib、moduleDefs 三个域分别自格式版本 2/3/4 起携带；导入更低版本口令时对应域为 undefined，**本机现有数据保持不动**。level 的旧数据在导入时迁移：缺 rows 补 28、按下限钳制取整、模板墙格并入基地格全集。
- **堡垒库的同 id 覆盖语义**：口令 = 配置搬运，导入方数据为准——口令中每条堡垒按 id upsert 进本机 customs（同 id 整条覆盖，包括对本机内置覆盖条目的还原），本机独有的其它自定义堡垒保留不受影响。合并先把自定义条目并入注册表、再校验收录口令携带的出战 id（存在才收录），保证新导入的自定义堡垒可被直接设为出战。

### 9.4 与战场/炮塔域的口令边界

口令是**全配置搬运**的单一通道，各域携带内容如下：

| 域 | 口令字段 | 携带内容 | 落盘键 |
| --- | --- | --- | --- |
| 炮塔 | `turretDefs` | 炮塔定义全量（内置当前状态 + 自定义） | `td-turret-defs` |
| 弹丸 | `projectileArts` | 弹丸美术库全量 | `td-projectile-arts` |
| 战场 | `level` | 关卡配置（地形/物体/建造区/纵深等） | `td-level-config-v7` |
| 素材 | `assets` | 素材库用户上传条目（内置素材不随口令） | 素材库通道 |
| 堡垒 | `fortressLib` | 仅自定义条目与内置覆盖条目 + 出战选择；内置出厂定义不携带（导入方使用自己的内置） | `td-fortress-lib-v1` |
| 模块 | `moduleDefs` | 模块库全量 | `td-module-defs` |

边界要点：堡垒域**不携带**堡垒的出厂内置定义、不携带对局状态（血量/热量/模块实例等局内数据一律不出门）；炮塔域不携带炮位布局（炮位属于堡垒定义，随 fortressLib 走）；素材域只携带用户上传条目，堡垒/炮塔定义中以素材库 id 引用的贴图依赖口令同包的 assets 还原，内置素材与 `/res` 路径资源由导入方本地提供。各域 localStorage 键互相独立，口令导入时缺失的域不动本机数据（§9.3），堡垒库内部再按同 id 覆盖语义细粒度合并。
