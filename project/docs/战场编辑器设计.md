## 规划中（未落地）：赤色要塞式单机关卡 · 范围拆解（2026-08-20）

> 需求（用户）：对战场编辑器进行深入开发，主要实现单机关卡战场，参考红白机《赤色要塞》
> （Jackal，1988）的过关游戏设定。本节为动工前的范围拆解，分期与拍板项确认后转入正式版本开发。
> plan.md 待开发记录汇总有同名条目（工作量：大，系统级特性）。

### 0. 现状基础（可复用，比预期好）
- **地图尺寸已不限**：v1.41 起 ROWS/COLS 仅保留下限（20×12），上限放开 → 长关卡数据层现成
- **相机雏形已存在**：渲染层有 viewY 视口 + clampViewY 钳制 → 卷轴跟随是在既有视口上做跟随策略，不是从零造相机
- **物体系统现成**：rock/ruins/barrel 已具备 hp/blockMove/blockProjectile/height → 交互物扩展有底子
- **堡垒本身就是可驾驶载具**（v2.51 双底盘手感）→ 与赤色要塞「开车过关」天然契合，这是最大契合点
- 固定波次队列（buildWave/spawnQueue）→ 防守模式保留不动，触发器为推进模式新增

### 1. 要素清单（赤色要塞 → 本游戏）
**A. 推进模式（核心新增；现有防守模式全程保留）**
- A1 纵向长关卡（3~10 屏纵深）+ 起点/终点区标记
- A2 卷轴相机：跟随堡垒推进（赤色要塞式：自由驾驶，顶到屏幕边缘带卷轴）
- A3 胜利条件类型化：抵达终点（推进）/ 坚守波次（防守，现有）/ 歼灭 / 时长
**B. 触发器系统**
- B1 区域触发刷怪（伏兵：进入矩形区域出怪）——赤色要塞伏击感的来源
- B2 事件类型扩展：增援/路障激活/补给/文字提示
- B3 编辑器触发器摆放层（区域框 + 事件参数，可视化）
**C. 场景交互物**
- C1 **可互动的建筑或生物**（拍板 2026-08-20：无人质营救；交互形态与奖励挂钩另定）
- C2 路障（须摧毁或绕行）/ 补给点
**D. Boss 波**（关底决战标记：末段高强度敌群或大型敌人）
**E. 关卡链**
- E1 多关卡库 + 过关结算界面
- E2 进度存档（关卡解锁）+ 关卡选择界面

### 2. 分期建议
- **一期 MVP「推进模式」**（工作量 中~大）：A 全部 + B1——把「开车闯关、沿途伏击」的赤色要塞感立起来；触发器仅区域刷怪一种，事件类型后扩
- **二期「战场有血有肉」**（中）：B2/B3 + C + D——交互物与奖励、Boss 波、触发器编辑器完善
- **三期「战役」**（中）：E 全部——关卡链、结算、进度存档、选关
- 原则：防守模式任何一期都不受影响；每期独立可玩、独立交付

### 3. 拍板结论（2026-08-20，用户逐项确认）
1. **推进模式禁用基地建造**（基地格/防御墙体系仅属防守模式）
2. **相机 = 自由推进 + 顶到屏幕边缘带卷轴**（赤色要塞原味，非自动卷轴）
3. **失败条件 = 玩家战车结构值归零**（沿用现有）；**后期增加驾驶员控制模式**：战车被毁后驾驶员可下车寻找空战车重新启动战斗——驾驶员本质是一个特殊战车单位（记入待开发衍生项）
4. **无人质营救**；关卡中设置**可互动的建筑或生物**（交互物形态另定，不绑定救人质升级武器）
5. **战役规模不限定关数**；**每个关卡限定玩家可使用的战车，包括炮塔和模块**（选关 = 限定配装池）；**游戏过程中可获得新炮塔和模块，但均不继承到下一关**（关内获得、关末清零，每关独立配装）
6. **补充设定：单机关卡用于解锁战车车体、炮塔和模块**——未解锁的装备在多人联机模式下不可用（衍生两项待开发：装备解锁系统、多人联机模式）；**解锁系统单机先行方案已确认**：解锁数据格式先行落地（装备标记解锁来源关卡 + 解锁状态存档），联机模式将来读取同一份数据做准入校验

### 4. 衍生待开发项（由拍板结论引出）
- **驾驶员控制模式**：驾驶员**并非战车**（用户 2026-08-20 澄清）——大量战车参数不适用（无底盘/炮位/装甲/热量/履带轮组等），相当于一个**全新的轻量单位类型**：步行移动、上下车交互、登入空战车续战；战车被毁不直接判负、驾驶员存活即续命。**工作量：大**（新单位类型（非 FortressDef 派生）+ 操控切换 + 与敌人索敌/碰撞系统的交互矩阵）
- **装备解锁系统**：关卡 → 解锁战车车体/炮塔/模块的进度数据；编辑器侧配置各关解锁项；解锁状态存档。**单机先行已确认**（2026-08-20）：解锁数据格式先行，联机读取同一份数据。**工作量：中**
- **多人联机模式**（被解锁系统引用为前提，本身未立项）：网络同步/房间/对局规则均为空白。**工作量：特大（独立专项，不在本拆解范围）**

## 版本补充（近期变更速览）

> 版本 v1.55 · 2026-08-16
> 前置已落地：场景编辑器（宽/纵深可配）。移动堡垒/内部模块/堡垒热量池见《堡垒编辑器设计》。

> v1.55 性能包（本轮已落地，针对"开波后卡顿"）：
> ① 寻路距离场重构：障碍格一次性栅格化（原每邻居 blockerAt 全表扫描 objects/walls.cells/buildings）、
> 二叉堆 Dijkstra（原 O(n²) 线性扫最小值）、按 pathVersion 缓存（原每 tick 无条件重算）——
> tick 基准 0.93ms → 0.18ms（5×），缓存命中时寻路 ≈0.001ms。
> ② 画布分辨率 dpr 上限 2（像素风 dpr=3 无视觉收益，移动端填充率省约 55%）。
> ③ 插值查找表按 prev 状态身份缓存（原每帧重建 3 个 Map，60fps GC 压力）。
> ④ 新增 __perf 探针（draw/tick 耗时均值与峰值，后续性能诊断用）。
> ⑤ 仿真回归按 v1.54 新参数全量校准（转向速率语义由"半径限速"变为"转向速度 25°/s 限速"，
> 弧线半径上限 0.6rad/s 仅在陀螺稳定器等高转向配置下触顶；俯仰 k=gain×0.5=1）。
> 回归：tsc/sim 386 项全绿；e2e 7/7——启动/探针/dpr 上限/交战推进/高速驱动位移。

> v1.41 修正（本轮已落地）：**战场宽度/纵深上限取消**。原 COLS_MAX=48 / ROWS_MAX=24 硬上限删除——
> level.ts 的 reanchorCols/reanchorRows/parseLevel 迁移与 config_transfer.ts 口令导入均只保留下限

> v1.49 重构（本轮已落地）：**基准格全设备统一 + 竖版自适应视口**。废除「按容器尺寸适配基准格」
>（iPhone ≈19px/格、iPad ≈50px/格，与贴图 30px=1格 设计基准脱节 → 堡垒/战场比例随设备漂移），
> 改为固定 BASE_CELL=30px/格（config.ts），任何设备/朝向/屏幕尺寸下网格与贴图比例恒定一致，
> zoom=1 时贴图逐像素吻合。竖版（容器高>宽）视口自适应改为 12×20 格（横版 20×12 宽高对调），
> 画布尺寸 = 30×视口格数（横版 600×360 / 竖版 360×600）；画布超出小屏容器时居中裁边（相机跟随
> 堡垒不受影响）；clampViewX/Y 在视口大于世界时安全钳 0。渲染侧 zf/zm 基准由 cell/(W/VIEW_COLS)
> 统一为 cell/BASE_CELL。编辑模式拖动换算改用 size.cell（横竖版通用）。
> 回归：tsc/sim 全绿；e2e 8/8——横版画布 600×360、竖版 360×600、小屏横版仍 600×360 不缩水、
> 内部分辨率 = CSS 尺寸 × dpr。
