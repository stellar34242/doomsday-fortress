# 关卡编辑器设计文档

## v2.76 敌方直线实弹测试模式与装甲跳弹（2026-08-22）

- 为集中测试四向装甲，现有五类敌人全部临时统一为远程直线实弹攻击；原有血量、速度、体型、赏金、空地属性等差异保持不变。
- 每类敌人新增 `attackRange / attackInterval / projectileSpeed / projectileDamage / penetration`：进入射程后停车，按间隔向堡垒中心发射独立敌方弹丸；驶出射程后停止射击并继续追踪。
- 敌方弹丸使用高速线段与旋转后的主体贴图 Alpha 求首次不透明像素交点，避免低帧率/高弹速穿模；弹丸会越过底座、履带、轮胎和主体透明区，进入主体后才结算受击方向、跳弹与贴花。贴图 Alpha 尚未就绪时回退中央主体框，不使用整车外框。视觉使用暖红曳光与亮色弹头，和玩家弹丸分池。
- 出厂参数：行尸 8格/1.5秒/穿深3，冲核尸 7格/1.1秒/穿深2.5，重甲尸 9格/2.2秒/穿深6，飞蝗 10格/0.9秒/穿深2，疾行尸 7.5格/1.2秒/穿深3。
- 概率穿深失败时结构零伤害，生成跳弹浮字、反射曳光、金属火花与擦痕；护盾仍在装甲判定之前吸收实弹。

## v2.70 防守波次自动节奏（2026-08-22）

- **主界面自动推进**：移除手动“开波”按钮。防守任务 HUD 只显示当前/总波数及部署、休整或下波倒计时；生存与推进目标不显示波次概念。
- **等待波次**：`waveWait=true` 时，当前波全部敌人、伏击队列和事件队列清空后进入 `restTime` 秒休整，再自动开始下一波。默认休整 60 秒；首波使用同一时长作为部署倒计时。
- **接踵波次**：`waveWait=false` 时不进入休整。本波普通队列最后一名敌人登场后开始 `overlapTime` 倒计时，到点即排入下一波，上一波残敌不会阻止接续。默认接踵 5 秒；首波直接开始交战。
- **配置与兼容**：防守目标扩展为 `{ type:'defend', waves, waveWait, restTime, overlapTime }`；旧关卡缺字段时迁移为“等待、60 秒休整、5 秒接踵”。编辑器根据开关互斥启用休整/接踵输入，禁用字段不参与运行时结算。

## v2.64 通用事件、交互物、Boss 与关卡链（2026-08-22）

- **统一动作模型**：区域事件、场景交互物和 Boss 阶段共同使用有序 `actions[]`，支持等待、刷敌、Boss、任务提示、废料奖励、切换目标、启停交互物和完成关卡。等待动作会阻塞本序列，其余序列可并行推进；事件队列未结束时不会提前结算波次。
- **兼容迁移**：关卡格式升级到 v10。v9 及更早的伏击配置自动转换为“等待 + 刷敌”动作，旧 `delay/interval/enemies` 字段仍保留用于无动作旧数据的精确兼容；地图改尺寸时交互物与区域一起重锚定。
- **场景交互物**：检查点、补给、闸门和任务目标均为可视矩形区域，支持启用、仅一次、进入触发及动作序列；编辑器左栏和画布可新增、选中、移动、改尺寸并配置动作。
- **Boss 阶段**：Boss 动作可配置敌种、名称、生命倍率、体型倍率、多个生命阈值阶段和击败动作。阶段按阈值每场只触发一次，战场显示名称与总生命条，击败后可继续编排奖励、提示、刷怪或通关。
- **关卡链与进度**：关卡条目新增下一关 ID 和完成奖励；胜利时持久记录已完成关卡与累计战役奖励，结算层显示奖励并可直接进入下一关。链条引用在导入时校验，缺失、自指目标自动清除。
- **设定依据**：动作模型选择“可组合的小动作”而非持续增加专用触发器类型，使区域、交互物和 Boss 复用同一运行时与编辑器；Boss 阶段动作按生命百分比而非固定血量，保证生命倍率调整后阶段节奏仍保持一致。

## v2.63 固定面板整合（2026-08-21）

- **统一入口框架**：切换到“关卡编辑器”后继续保留 DEBUG 顶栏和全部编辑器页签，不再关闭面板进入独立全屏工作区。
- **固定内容区域**：左侧关卡库与右侧场景画布共同显示在顶栏下方的固定内容区；编辑时隐藏游玩 HUD，透明交互层只保留 DEBUG 框架，画布与列表保持可操作。
- **草稿生命周期**：切换到其他编辑器或关闭 DEBUG 会放弃当前草稿并恢复进入编辑前的试玩关卡；“应用并试玩”保存全库、切换活动关卡并退出面板。

## v2.62 多关卡库（2026-08-21）

- **库结构**：新增 `LevelLibrary { version, activeId, levels[] }`，每个条目持有稳定 ID、名称和完整 `LevelConfig`；最多载入 50 关。运行时 `LEVEL` 继续保持单例接口，但其内容始终镜像 `activeId` 指向的试玩关卡，因此引擎无需全面改写。
- **迁移与持久化**：新增 `td-level-library-v1`。首次没有关卡库时，自动读取旧 `td-level-config-v7` 并迁移为“关卡 01”；保存库时同时写旧单关卡兼容镜像。坏库、空库、重复 ID、坏活动 ID和空名称均有归一化回退。
- **编辑语义**：关卡编辑器支持新建、复制、重命名、删除、上下排序和列表切换。编辑非试玩关卡时，画布临时把 `LEVEL` 切到该草稿以复用现有渲染/碰撞边界；原试玩关卡另存快照。“退出编辑”完整恢复原试玩关卡，“应用并试玩”才把全部草稿原子写入库，并把当前选中关卡设为活动关卡后重开。
- **口令**：配置口令升级到 v5，新增完整 `levelLibrary`，同时保留顶层 `level` 作为低版本兼容镜像；v1–v4 口令导入时自动包装成单关卡库。
- **编辑器操作**：列表显示顺序、模式、尺寸、伏击数量和当前试玩标记；单关卡时禁止删除，库上限为 50。复制使用当前未应用草稿，避免刚编辑的内容在复制时丢失。

## v2.61 关卡编辑器工作区重构（2026-08-21）

- **入口与布局**：DEBUG 中“战场编辑器”改名为“关卡编辑器”，点击后直接进入编辑工作区，不再经过参数页再点“进入场景编辑”。工作区采用左侧关卡/属性栏、右侧常驻场景画布；编辑期间暂停本局，应用后统一保存并重开。
- **关卡列表框架**：左侧加入关卡列表，当前先承载单个“关卡 01”，显示模式、尺寸和伏击区域数量；结构与视觉已为后续真正的多关卡数据层预留位置，本期不提前引入关卡库迁移风险。
- **伏击区域场景化**：左侧可新增和选择伏击区域，并直接编辑名称、启用状态、矩形、次数、冷却、延迟、间隔与敌群。选择条目会自动切换伏击笔刷；画布点击已有区域即可选中，点击空地移动当前区域，尺寸在同一左栏调整。
- **内容收敛**：删除“新增建筑”“新增初始炮塔”按钮，并从场景工具中移除对应新增笔刷。旧配置中的建筑和初始炮塔仍保持读取、渲染和迁移兼容，不破坏已有存档。
- **后续边界**：真正的多关卡库已在 v2.62 落地；下一阶段继续交互物/Boss 波与多动作事件编排。

## v2.60 区域伏击触发器（2026-08-21）

- **数据与迁移**：关卡配置升级到 v9，新增 `triggers[]`。每个触发器包含矩形区域、启用状态、触发次数上限、冷却、首次延迟、单位间隔，以及五类现有敌人的数量；旧存档/口令自动补空数组，地图改宽或改纵深时区域同步重排、收缩或丢弃。
- **触发语义**：以堡垒中心从区域外进入区域内的边沿作为触发事件；持续停留不重复触发，必须先离开，再满足冷却和次数上限才可重触发。此口径避免低帧率或边界抖动把同一次进入放大成多次伏击。
- **刷怪队列**：伏击使用独立于普通波次的延迟队列，首名敌人按首次延迟出现，后续按单位间隔依次出现；刷怪点以触发器 ID、触发次数和队列序号确定性地分布在区域四周。待刷伏击会阻止波次提前结算，但不会篡改普通波次队列。
- **编辑器**：战场编辑器可新增、删除、选择和精确编辑伏击区域及敌群参数；场景编辑新增“伏击区域”笔刷。画布以红色虚线和名称显示启用区域，选中项加粗高亮，禁用项显示灰色。
- **本期边界**：当前触发动作专注敌群伏击。交互物、Boss 波、目标/对话/奖励等多动作事件，以及触发器复制与更完整的事件编排，留给下一期。

## v2.59 推进模式骨架（2026-08-21）

- **模式与区域**：关卡配置升级到 v8，新增 `mode: defend | advance`、`startZone` 与 `finishZone`。旧存档/旧口令自动迁移为防守模式并补齐默认起终点；地图宽度/纵深重排时区域与其他关卡元素一起迁移并钳制在界内。
- **开局与波次**：推进模式从起点区域居中生成堡垒，跳过备战阶段直接进入交战；清空当前敌群后自动接续下一波，不出现波间建造停顿。堡垒装配仍由关外预设体系承接，推进关内不开放临时建造窗口。
- **目标**：新增 `{ type: 'reach' }`。堡垒中心进入终点矩形即胜利；若同 tick 船体归零，毁灭序列与判负优先，避免撞线时已毁仍胜。
- **相机**：推进游玩态采用 22%/78% 双轴安全带——堡垒可在屏幕中央区域自由驾驶，越过边缘带才推动视口；视口始终钳制在地图范围。防守模式仍保持居中跟随，场景编辑仍保持手动拖动画布。
- **编辑器与表现**：战场编辑器新增模式选择、起终点精确坐标/尺寸，以及“玩家起点”“关卡终点”地图笔刷；编辑态以绿色/金色虚线区域预览，进入编辑时镜头自动居中起点。游玩态终点显示金色撤离区，HUD 显示直线剩余距离（米）。
- **本期边界**：区域伏击触发器已在 v2.60 落地；交互物、Boss 波与多动作事件仍留给后续。

## v2.58 关卡目标系统一期（2026-08-21）

- **数据结构**：`LevelConfig.objective` 使用可辨识联合：防守目标现扩展为 `{ type: 'defend', waves, waveWait, restTime, overlapTime }`，另有 `{ type: 'survive', duration }`。波数限制 1–99，生存时长限制 10–3600 秒；旧存档和旧配置口令缺字段时迁移为 6 波保卫及 v2.70 默认节奏。
- **胜负分派**：现有“守完固定 6 波”改为读取关卡目标；生存目标只累计 `combat` 阶段时间，波间整备不计时，到时即胜。堡垒毁灭序列优先于同 tick 生存到时，避免已被击毁却误判胜利。
- **编辑器与 HUD**：战场编辑器新增目标类型与参数控件；HUD 在保卫模式显示当前/总波数，在生存模式显示剩余秒数，结算文案同步目标类型。
- **编辑器修正**：移动堡垒默认关卡本就没有基地格；“基地格为空”仅在同时配置了核心、建筑、初始地面炮塔或墙时才作为阻断警告，默认关卡可正常应用并重开。
- **后续边界**：`destroy` 依赖敌对目标实体，`escort` 依赖友军移动强化，仍留在待开发 #22 后续梯队。

## v2.57 地面弹坑（2026-08-21）

- **触发边界**：爆炸事件首次被渲染层观察时生成弹坑，半径按事件 `r` 缩放并设置上下限，因此堡垒主爆自然形成最大坑；普通弹丸未命中且射程耗尽时，引擎只发一个 `groundImpact` 视觉事件，生成固定小坑，不附带弹药 ID，也不触发爆炸伤害。
- **状态归属**：弹坑是纯装饰性 decal，独立在 `craters.ts` 中维护，不进入游戏状态、不参与存档、碰撞和数值结算。这样既保持引擎确定性，也避免长期地表痕迹扩大模拟状态。
- **绘制与风格**：启动后按 seed 缓存 16 张离屏 Canvas 纹理，组合中心焦黑、浅色隆起边缘和少量碎屑；绘制顺序为地形 → 弹坑 → 场景物体 → 履带印，保证坑属于地表且新鲜履带能压过旧坑。
- **生命周期**：最多保留 120 个，超出按生成顺序 FIFO 淘汰；寿命 45 秒，前 30 秒常显，最后 15 秒线性渐隐。选择较履带印更长的寿命，是为了让爆炸在一段战斗中留下可读的战场疤痕，同时严格限制显存与逐帧绘制成本。

## 规划中（未落地）：赤色要塞式单机关卡 · 范围拆解（2026-08-20）

> 需求（用户）：对战场编辑器进行深入开发，主要实现单机关卡战场，参考红白机《赤色要塞》
> （Jackal，1988）的过关游戏设定。本节为动工前的范围拆解，分期与拍板项确认后转入正式版本开发。
> plan.md 待开发记录汇总有同名条目（工作量：大，系统级特性）。

### 0. 现状基础（可复用，比预期好）
- **地图尺寸已不限**：v1.41 起 ROWS/COLS 仅保留下限（20×12），上限放开 → 长关卡数据层现成
- **相机雏形已存在**：渲染层有 viewY 视口 + clampViewY 钳制 → 卷轴跟随是在既有视口上做跟随策略，不是从零造相机
- **物体系统现成**：rock/ruins/barrel 已具备 hp/blockMove/blockProjectile/height → 交互物扩展有底子
- **堡垒本身就是可驾驶载具**（v2.51 双底盘手感）→ 与赤色要塞「开车过关」天然契合，这是最大契合点
- 固定波次队列（buildWave/spawnQueue）→ 防守模式保留不动，触发器为推进模式新增

### 1. 要素清单（赤色要塞 → 本游戏）
**A. 推进模式（核心新增；现有防守模式全程保留）**
- A1 纵向长关卡（3~10 屏纵深）+ 起点/终点区标记
- A2 卷轴相机：跟随堡垒推进（赤色要塞式：自由驾驶，顶到屏幕边缘带卷轴）
- A3 胜利条件类型化：抵达终点（推进）/ 坚守波次（防守，现有）/ 歼灭 / 时长
**B. 触发器系统**
- B1 区域触发刷怪（伏兵：进入矩形区域出怪）——赤色要塞伏击感的来源
- B2 事件类型扩展：增援/路障激活/补给/文字提示
- B3 编辑器触发器摆放层（区域框 + 事件参数，可视化）
**C. 场景交互物**
- C1 **可互动的建筑或生物**（拍板 2026-08-20：无人质营救；交互形态与奖励挂钩另定）
- C2 路障（须摧毁或绕行）/ 补给点
**D. Boss 波**（关底决战标记：末段高强度敌群或大型敌人）
**E. 关卡链**
- E1 多关卡库 + 过关结算界面
- E2 进度存档（关卡解锁）+ 关卡选择界面

### 2. 分期建议
- **一期 MVP「推进模式」**（工作量 中~大）：A 全部 + B1——把「开车闯关、沿途伏击」的赤色要塞感立起来；触发器仅区域刷怪一种，事件类型后扩
- **二期「战场有血有肉」**（中）：B2/B3 + C + D——交互物与奖励、Boss 波、触发器编辑器完善
- **三期「战役」**（中）：E 全部——关卡链、结算、进度存档、选关
- 原则：防守模式任何一期都不受影响；每期独立可玩、独立交付

### 3. 拍板结论（2026-08-20，用户逐项确认）
1. **推进模式禁用基地建造**（基地格/防御墙体系仅属防守模式）
2. **相机 = 自由推进 + 顶到屏幕边缘带卷轴**（赤色要塞原味，非自动卷轴）
3. **失败条件 = 玩家战车结构值归零**（沿用现有）；**后期增加驾驶员控制模式**：战车被毁后驾驶员可下车寻找空战车重新启动战斗——驾驶员本质是一个特殊战车单位（记入待开发衍生项）
4. **无人质营救**；关卡中设置**可互动的建筑或生物**（交互物形态另定，不绑定救人质升级武器）
5. **战役规模不限定关数**；**每个关卡限定玩家可使用的战车，包括炮塔和模块**（选关 = 限定配装池）；**游戏过程中可获得新炮塔和模块，但均不继承到下一关**（关内获得、关末清零，每关独立配装）
6. **补充设定：单机关卡用于解锁战车车体、炮塔和模块**——未解锁的装备在多人联机模式下不可用（衍生两项待开发：装备解锁系统、多人联机模式）；**解锁系统单机先行方案已确认**：解锁数据格式先行落地（装备标记解锁来源关卡 + 解锁状态存档），联机模式将来读取同一份数据做准入校验

### 4. 衍生待开发项（由拍板结论引出）
- **驾驶员控制模式**：驾驶员**并非战车**（用户 2026-08-20 澄清）——大量战车参数不适用（无底盘/炮位/装甲/热量/履带轮组等），相当于一个**全新的轻量单位类型**：步行移动、上下车交互、登入空战车续战；战车被毁不直接判负、驾驶员存活即续命。**工作量：大**（新单位类型（非 FortressDef 派生）+ 操控切换 + 与敌人索敌/碰撞系统的交互矩阵）
- **装备解锁系统**：关卡 → 解锁战车车体/炮塔/模块的进度数据；编辑器侧配置各关解锁项；解锁状态存档。**单机先行已确认**（2026-08-20）：解锁数据格式先行，联机读取同一份数据。**工作量：中**
- **多人联机模式**（被解锁系统引用为前提，本身未立项）：网络同步/房间/对局规则均为空白。**工作量：特大（独立专项，不在本拆解范围）**
