## 1. 项目概述

末日废土风格的战车驾驶与战斗游戏（Web 原型），**以横屏为主要体验，同时兼容竖屏**。玩家驾驶可机动的堡垒战车（履带/轮式双底盘运动学），在车体炮位上挂载炮塔，对抗废土上的丧尸与其他敌对单位；堡垒结构值归零会触发三段式毁灭演出并判负。

- **技术栈**：React 19 + TypeScript + Vite 7 + Tailwind 3.4 + Canvas 2D（无游戏引擎）
- **架构关键**：`src/game/` 是纯逻辑层（不 import DOM），`engine.ts` 的 `tick(state, dt)` 是唯一状态推进入口；逻辑 10Hz 固定步长，渲染 60fps rAF 插值
- **引擎确定性纪律**：引擎内**禁止 Math.random**——所有随机走 seed 化（事件 id 作种子），保证 sim 无头回归可复现
- **三大编辑器**：堡垒编辑器（车体形状/炮位/底盘/机动参数）、炮塔编辑器（弹丸库/特效/美术分层）、战场编辑器（关卡网格/地形/物体），全部经 DebugPanel 进入，改动即时生效并持久化

## 4. 开发流程（两条通道，严格执行）

### 快速通道（纯数值/文案/贴图/口令/参数微调）
改代码 → `npm run typecheck` → `npm run build` → 版本快照。`build` 已自动同步 `public/` 到 `dist/`。**跳过** sim/e2e/文档同步，plan.md 不记。

### 完整流程（机制变更，必须走全）
1. **改代码**——同一文件的多次编辑**严格串行，每次编辑后 grep 验证**（血泪教训，见 §5）
2. 在 `project/` 执行 `npm run verify`；该命令串行完成类型检查、sim 回归、TypeScript/Vite 构建和 `public/` 素材同步
3. 确认末尾同时出现 `ALL CHECKS PASSED`、`✓ built`、`✓ VERIFY PASSED`；新机制 = 加新断言，改行为 = 改旧断言语义
4. **e2e**：复制 `handover_tools/e2e_driver_template.html` 为 `dist/__vXXX.html`（vite build 会清空 dist，每次重建复制）→ `npx vite preview --port 4599` → headless chromium 访问 `/__vXXX.html`，期望 `data-result="CANVAS_OK"`（驱动页 iframe 必须加载 `/` 而非 `/index.html`——react-router）
5. 版本快照（平台工具 website_version_manager，type=static）
6. plan.md 记一行（版本 + 摘要）；设计文档更新对应章节（含设定依据）
7. 三向同步：project → 部署目录 docs/、输出根目录平铺 docs、plan.md；源码重打 zip

## 5. 工程纪律与环境陷阱（血泪教训）

1. **幽灵编辑（最高优先级）**：对同一文件的并行编辑会基于同一快照竞争，后写覆盖先写且**双方都报成功**。已发生 4 次。纪律：**同文件编辑严格串行 + 每次 grep 验证落盘**。
2. **依赖必须按当前平台重建**：旧交接缓存来自 Linux，不能在 Windows 复用原生 esbuild/Rollup。统一以 `package-lock.json` 为准执行 `npm ci`；Windows 可运行 `handover_tools/restore_deps.ps1`，macOS/Linux 可运行 `handover_tools/restore_deps.sh`，两者安装后都会自动执行完整验证。
3. **sim 口令文件**：个别素材字节级断言需要 `TD_TOKEN_FILE` 指向配置口令文本（base64），已固化为 `handover_tools/td_sim_token.txt`（其 upload-2 贴图与库内 dualgun_s1.png 字节一致）。若将来素材再替换导致断言失败，按断言提示更新口令或改断言为魔数/尺寸校验（v2.16 有先例）。
4. **vite build 清空 dist**：e2e 驱动页每次重建后仍需重新复制；`npm run build` 已通过 `copy-public.mjs` 自动把 `public/` 同步进 `dist/`。
5. **引擎纯净**：不 import DOM、不用 Math.random（seed 化）；渲染层才允许 performance.now/document。
6. **预览与战场共用画法**：改爆炸/粒子/命中视觉，战场和编辑器预览走的是 fxDraw.ts 同一组函数（v2.55 已统一粒子池/爆炸层/命中闪光）；**炮塔美术预览（drawArtPreview/drawPreviewRack）仍是平行实现**（待开发 #15），改炮塔分层绘制时需两边都改。
7. **语言**：全部文档/注释/UI 用中文；提交信息中文。

## 6. 核心系统速览

- **堡垒机动**（engine.ts）：加速度驱动速度向量 → 轴分离位移（撞墙停该轴、贴墙滑动）；履带 = 差速转向，轮式 = 自行车模型（前轮转角 steerMax/steerRate、轴距、横向附着 gripMax 钳制）；转向半径 turnRadius>0 时覆盖底盘物理
- **摇杆**（GamePreview.tsx）：角度 = 目标朝向（航向+摇杆速率跟踪），幅度 = 速度；防抖 = One Euro 平滑滤波（编译期开关 `STICK_ANTI_JITTER` 可回退迟滞旧案，参数与依据见堡垒文档 §3.2）
- **毁灭序列**（v2.53）：hp≤0 → dyingT 状态机（内伤小爆 0/0.25/0.55s → 主爆 AOE 0.8s → 余烟至 2.2s 判负）；判负与毁灭事件解耦（为驾驶员模式预留，待开发 #6）
- **爆炸视觉**（v2.54 + fxDraw）：火球/软边冲击环/瞬时照明/拉丝火花四层程序化画法，弹丸库 explosion 组 fireball/shock/flash/streak 四参数可调
- **索敌**（v2.49）：标签式（目标偏好/排除/约束 + 资源标签），预留键位等待敌对堡垒/僚机等实体（待开发 #4）
- **地面贴花**：履带印由 `fortressFx.ts` 管理；弹坑由 `craters.ts` 管理，监听爆炸/落地事件首见并在地形之上、物体与履带印之下绘制，120 个 FIFO、45 秒寿命（末 15 秒渐隐）
- **fxSeen 模式**（render.ts）：事件首见 Map（id → 首见时间戳），特效生命周期由渲染层推演，引擎只发一次性事件
- **配置口令**（config_transfer.ts）：分域格式版本（assets/fortressLib/moduleDefs/level 各自版本号），低版本口令导入时对应域保持本机数据不动
