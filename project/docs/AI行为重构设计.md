# 战斗 AI 设计文档

> 状态：已实现  
> 版本：单位库 v19  
> 日期：2026-09-01  
> 范围：单位进入战斗后的单位 AI、炮塔 AI 与弹体 AI；不包含军官性格

## 1. 设计目标

战斗 AI 只回答三个问题：优先打谁、希望站多远、在距离带内如何移动。关卡编辑器中的停留、坚守、随机、路线、接近和跟随仍属于非战斗行为，不被塞进战斗 AI。

```text
关卡非战斗行为
    │ 发现合法目标 / 受到攻击 / 同组成员接战 / 事件触发
    ▼
单位战斗 AI：首选目标 → 站位区间 → 移动意图
    ├─ 炮塔 AI：各炮塔独立瞄准、开火，优先单位主目标
    └─ 弹体 AI：导弹制导、延迟制导、重新索敌
    │ 失去全部敌情并完成短暂确认
    ▼
恢复关卡行为；需要归位的行为先返回原位
```

核心原则：

- 玩家、友方、敌方和中立敌对单位共用同一套战斗规则，阵营只决定敌对关系。
- 玩家直接控制的载具不运行单位移动 AI，也不受单位视野限制；自动炮塔仍使用炮塔 AI。
- 单位 AI 不直接替炮塔选择最终开火目标，炮塔可以在主目标非法时攻击其他合法目标。
- 非玩家单位的弹药和电量可保持无限，但产热、过热、散热等武器规则一致。
- 本期不实现军官性格。以后若加入，作为与单位实例关联的上层修正，不扩充当前三个基础选项。

## 2. 编辑器暴露参数

每个单位模板只暴露以下三个战斗 AI 选择项：

| 参数 | 选项 | 含义 |
| --- | --- | --- |
| 首选目标 | 玩家主控单位 | 优先玩家当前直接控制的载具；堡垒防御模式中指当前可控堡垒。 |
|  | 玩家阵营 | 优先阵营为“玩家”的单位和当前可控堡垒。 |
|  | 所有敌对 | 所有合法敌人按距离竞争，但不会主动选择“中立敌对”。 |
| 站位 | 最远射程 | 取能攻击当前目标的炮塔中最长最大射程，目标为 85%，75%～95% 视为站位带。 |
|  | 最优射程 | 选择可同时覆盖炮塔数量最多的射程交叠区间；并列时先选更宽，再选更远的区间。 |
|  | 最近射程 | 取能攻击当前目标的炮塔中最短最大射程，目标为 50%，40%～60% 视为站位带。 |
| 移动 | 环绕 | 在站位带内侧向环绕目标。 |
|  | 远离 | 在站位带内向最远边界靠拢。 |
|  | 抵近 | 在站位带内向最近边界靠拢。 |
|  | 停止 | 到达站位带后停止主动平移；受限炮位仍可请求车体转向。 |
|  | 撞击 | 忽略普通站位，直接撞向合法的可碰撞地面目标。 |

“特殊”面板中的投送兵力属于单位能力，不参与上述三个选择项的仲裁。

不再暴露旧字段：索敌类型、移动类型、期望射程比例、射程容差、攻城允许目标、玩家控制 AI 选项。攻击类型仍在战斗参数面板中配置，因为它描述武器实现而不是 AI 性格。

## 3. 合法目标与首选规则

候选目标先经过硬过滤，再进行偏好排序。首选目标不能绕过任何硬规则。

硬过滤顺序：

1. 目标存活，且不是自身。
2. 双方阵营为敌对关系；中立单位永远不是战斗目标。
3. “中立敌对”不会成为单位主动选择的目标。
4. 目标位于本单位或同组单位共享视野内。
5. 至少一件可用炮塔、单位内置攻击或撞击能力能合法攻击该目标的空地类型。

排序规则：

1. 首选类别优先。
2. 同一偏好层中，主体外沿净距离更近者优先。
3. 完全相同时按目标池和运行时 ID 保证确定性。
4. 旧目标与新目标处于同一偏好层，且旧目标距离不超过新目标的 112% 加少量容差时，保持旧目标，防止频繁抖动。

首选目标不存在时会回退到其他合法敌人。炮塔先尝试单位主目标；若主目标不在自身射界、射程或空地能力内，再独立寻找其他合法目标。

## 4. 站位计算

站位只使用“当前还能工作且能攻击当前目标”的炮塔射程。单位内置攻击没有独立炮塔时，使用其战斗参数的 `0～range` 区间。所有计算均使用目标主体外沿到自身主体外沿的净距离。

### 4.1 最远射程

- 参考值：合法炮塔中最大的最大射程。
- 目标距离：参考值 × 85%。
- 合法站位带：参考值 × 75%～95%。
- 若武器存在最小射程，区间下界不得低于该最小射程。

### 4.2 最近射程

- 参考值：合法炮塔中最小的最大射程。
- 目标距离：参考值 × 50%。
- 合法站位带：参考值 × 40%～60%。
- 若武器存在最小射程，目标和区间下界同时向上钳制。

### 4.3 最优射程

- 把所有合法武器的最小、最大射程作为区间端点。
- 在相邻端点之间统计同时覆盖的武器数量。
- 选择覆盖数量最多的区间。
- 并列时优先更宽区间；仍并列时优先更远区间。
- 期望点取所选区间中点。

若当前目标没有任何可用射程，则站位区间为 0；无武器但选择“撞击”的地面载具仍可建立目标。

## 5. 移动仲裁

通用距离决策：

- 距离大于站位上界：接近目标。
- 距离小于站位下界：远离目标。
- 距离位于站位带内：执行所选移动方式。
- 远离会持续靠近站位带外沿；抵近会持续靠近站位带内沿；二者有小幅内部容差，避免来回切换。

环绕方向由运行时单位 ID 稳定决定，同一单位不会每帧随机换向。地面载具继续使用现有加速度、转向半径、倒车、碰撞和地形速度系统；飞行器继续使用现有飞行动力学，并可越过战场边界完成环绕后自主返场。飞行器、炮塔和弹丸在场外仍保持索敌、制导、射程与资源消耗逻辑，地图边缘不再作为飞行行为终止条件。

敌方地面单位接近玩家堡垒时使用关卡距离场绕开结构。对移动单位采用动态直达运动和现有阻挡碰撞。

## 6. 撞击失败回退

撞击必须同时满足：

- 自身为有碰撞车体的地面载具。
- 目标是可碰撞地面目标。
- 当前直达车道可达。

以下情况临时切换为“停止”：

- 目标不可碰撞。
- 目标位于空中。
- 路径不可达或持续没有前进进度。

空中或不可碰撞目标仍按当前站位区间接近、后退或停车，只是不执行直冲。路径不可达时原地制动，每 0.75 秒自动重检；连续 0.8 秒没有有效推进也判为暂时不可达。该状态只保存在运行时，不增加编辑器参数，也不写入存档。

## 7. 非战斗与接战边界

关卡行为控制器负责：

- 停留、坚守、随机、路线、接近、跟随。
- 初始朝向与移动/旋转锁定。
- 单位组共享视野。
- 任一组员受击或发现目标后让同组成员进入战斗。
- 脱战后返回原位，并恢复相应关卡行为。

单位获得合法战斗目标后，关卡移动行为让位给战斗 AI。丢失全部可见目标 0.25 秒后退出战斗；坚守、随机、路线和接近会先归位，停留以当前位置作为新锚点。事件命令仍可暂停、恢复或临时替换战斗 AI 的三个字段。

“锁定单位”、单位模板的 `bodyLocked`、移动速度为 0 和停留行为都只限制主体的平移/转向，不会关闭索敌、接战、脱战或武器。固定火力单位即使不能移动，也会在目标进入射程后正常攻击，并在整组失去敌情后清除目标、退出接战；没有炮位且没有内置攻击的固定单位允许保持纯场景对象用途，不产生无武器警告。

地面单位的坚守归位、随机、路线、接近和跟随共用 `nonCombatNavigation.ts` 的地格导航入口；飞行单位仍按原飞行动力学直达目标。导航按“单位通行轮廓 + 目标格 + 地图阻挡版本”共享距离场，移动目标每 0.25 秒或跨格刷新。随机点只从可达连通区域选取；路线节点不可跳过；连续约 0.65 秒无有效进展会触发脱困重算。路径只生成前视路点，底盘自身的加速、转向、碰撞和地形规则不变，动态单位避让继续由实体分离负责。

## 8. 炮塔与弹体 AI

### 炮塔 AI

- 每座炮塔独立检查射程、射界、最小射程、空地能力、排除标签、拦截能力与视野。
- 单位主目标获得最高优先级，但非法时不强制跟随。
- 受限炮位可请求车体把目标送入射界；全向炮位不干预车体。
- 固定视角武器即使“停止”也允许车体原地转向，解决固定炮塔载具无法瞄准的问题。

### 弹体 AI

- 导弹制导、延迟制导、垂发阶段和目标死亡后的重新索敌继续由 `missileAI.ts` 独立负责。
- 重新索敌遵守同一阵营敌对关系和空地合法性，不反向修改单位主目标。

### 单位内置攻击

- 实弹和即时命中都使用战斗参数中的装填时间；同一单位定义处于敌方或友方时，单位时间内的攻击次数一致。
- 即时命中不再复用近战接触判定，目标只要满足视野、合法性和射程即可结算。
- 近战按 `伤害 ÷ 装填时间` 换算为持续接触伤害，敌方、友方和护送单位使用相同口径，逻辑帧大小不会改变单位时间总伤害。
- 护送任务的特殊移动流程只负责前往终点；进入战斗后的射程、弹丸、即时命中和近战节奏仍复用上述统一规则。

## 9. 代码边界

| 文件 | 职责 |
| --- | --- |
| `ai/schema.ts` | 三字段协议、旧存档迁移、站位算法、距离决策、事件覆盖。 |
| `ai/combatTargeting.ts` | 阵营无关的候选过滤、目标排序和炮塔射程提取。 |
| `ai/nonCombatBehavior.ts` | 关卡行为、编组视野、接战/脱战和归位。 |
| `ai/nonCombatNavigation.ts` | 非战斗地面行为的共享距离场、可达区域、前视路点与卡住重算。 |
| `ai/allyCombatAI.ts` | 友方、玩家阵营 AI 单位的战斗循环。 |
| `ai/enemyCombatAI.ts` | 敌方、中立敌对单位的战斗循环与堡垒路径接近。 |
| `ai/vehicleCombatAI.ts` | 载具站位、环绕、撞击回退和受限炮位车体协同。 |
| `ai/turretAI.ts` | 所有阵营炮塔的独立索敌、评分、瞄准和开火许可。 |
| `ai/deploymentAI.ts` | 投送兵力状态机。 |
| `ai/missileAI.ts` | 导弹制导与重新索敌。 |
| `engine.ts` | 世界状态、移动学、碰撞、发射、伤害和特效执行端口。 |

AI 文件只负责观察与决策，不自行实现伤害、移动物理或渲染。这样可以独立测试算法，也避免 `engine.ts` 再次堆积阵营专用分支。

## 10. 数据迁移

单位库升级为 v19。旧字段加载时自动转换：

| 旧配置 | 新配置 |
| --- | --- |
| 堡垒索敌 | 首选玩家主控单位。 |
| 最近敌对、反载具、攻城等其他索敌 | 首选所有敌对；旧静态攻城目标不再作为单位战斗 AI 候选。 |
| `rangeEdge` | 最远射程 + 环绕。 |
| `holdRange` | 最远射程 + 停止。 |
| `direct` / `flyDirect` | 最近射程 + 抵近。 |
| `follow` / `stationary` / 其他旧移动 | 最优射程 + 停止；非战斗跟随由关卡行为继续保存。 |

旧攻击字段迁入战斗参数，不再由 AI 面板编辑。旧期望射程比例和容差仅保留为兼容数据，运行时不读取。

## 11. 性能评估

- 目标扫描沿用现有单位池与空间查询；主要新增成本是每个接战单位一次候选过滤和少量射程区间计算。
- 炮塔射程交叠只处理本车少量炮塔，复杂度约为 `O(W²)`，`W` 通常远小于 20，实际成本很低。
- 目标保持迟滞减少了重新排序、转向和路径抖动。
- 撞击路径检查采用 0.75 秒缓存，不会每帧重复完整检测。
- 不增加渲染、粒子或碰撞体数量；对移动端的主要压力仍来自单位数量、炮塔数量和弹丸数量，而不是三字段 AI。

相较旧结构，新结构减少阵营专用分支、互相覆盖的旧索敌/移动模式和参数组合歧义。性能开销预计为轻微增加，但可维护性、确定性和后续扩展性明显更好。

## 12. 验收口径

- 单位编辑器和事件 AI 覆盖只显示三个已敲定选项。
- 老单位库可无人工修改迁移并保存为 v19。
- 所有阵营使用同一目标、站位和移动计算入口。
- 炮塔优先单位主目标，同时保留独立合法目标选择。
- 三种站位区间按本文比例与重叠规则计算。
- 撞击遇到空中、不可碰撞或不可达目标时回退停止并自动重试。
- 关卡行为只在非战斗/脱战阶段运行；接战后由战斗 AI 接管。
- 主体被锁定或处于停留状态时仍能索敌和开火，丢失目标后仍能完成统一脱战。
- 敌我双方的即时命中受装填时间约束，近战按相同持续伤害口径结算。
- 类型检查、构建和浏览器交互验证通过。
